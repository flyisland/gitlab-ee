使用此 API 管理 [Geo 节点](../administration/geo/_index.md)。

先决条件：

- 您必须是管理员。

<a id="create-a-geo-node"></a>

## 创建 Geo 节点

创建一个 Geo 节点。

```plaintext
POST /geo_nodes
```

```shell
curl --request POST \
  --header "PRIVATE-TOKEN: <your_access_token>" \
  --url "https://primary.example.com/api/v4/geo_nodes" \
  -d "name=himynameissomething" \
  -d "url=https://another-node.example.com/"
```

| 属性                   | 类型    | 是否必需 | 描述                                                      |
| ----------------------------| ------- | -------- | -----------------------------------------------------------------|
| `primary`                   | boolean | 否       | 指定此节点是否应为主节点。默认为 false。 |
| `enabled`                   | boolean | 否       | 指示是否启用 Geo 节点的标志。默认为 true。 |
| `name`                      | string  | 是      | Geo 节点的唯一标识符。如果在 `gitlab.rb` 中设置了 `geo_node_name`，则必须与其匹配；否则必须与 `external_url` 匹配。 |
| `url`                       | string  | 是      | 面向用户的 Geo 节点 URL。 |
| `internal_url`              | string  | 否       | 在主节点上定义的 URL，从节点应使用此 URL 连接主节点。如果未设置，则返回 `url`。 |
| `files_max_capacity`        | integer | 否       | 控制此从节点的 LFS/附件回填最大并发数。默认为 10。 |
| `repos_max_capacity`        | integer | 否       | 控制此从节点的代码仓库回填最大并发数。默认为 25。 |
| `verification_max_capacity` | integer | 否       | 控制此节点的代码仓库验证最大并发数。默认为 100。 |
| `container_repositories_max_capacity` | integer  | 否 | 控制此节点的容器仓库同步最大并发数。默认为 10。 |
| `sync_object_storage`       | boolean | 否       | 指示 Geo 从节点是否应复制对象存储中的 blob 的标志。默认为 false。 |
| `selective_sync_type`       | string  | 否       | 仅同步指定的群组或分片。有效值：`"namespaces"`、`"shards"` 或 `null`。 |
| `selective_sync_shards`     | array   | 否       | 当 `selective_sync_type` == `shards` 时，要同步的项目的代码仓库存储。 |
| `selective_sync_namespace_ids` | array | 否      | 当 `selective_sync_type` == `namespaces` 时，应同步的群组 ID。 |
| `minimum_reverification_interval` | integer | 否 | 代码仓库验证的有效期（以天为单位）。过期后将重新验证。在从节点上设置时无效。 |
| `blob_download_timeout`           | integer | 否       | blob 复制的超时时间（以秒为单位）。默认为 28800。最大值为 86400。 |

示例响应：

