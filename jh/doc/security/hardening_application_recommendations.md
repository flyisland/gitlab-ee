您可以通过 Web 界面控制极狐GitLab 实例的加固建议。

## 先决条件

您必须拥有管理员权限。

## 系统钩子

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **系统钩子**。

在典型的加固环境中，内部信息不会传输或存储在系统外部。对于离线环境系统，这是隐含的。系统钩子提供了一种方式，让环境中的本地事件能够根据触发器将信息传递到环境之外。

此功能的用例是受支持的，特别是通过远程系统监控系统。但是，部署系统钩子时必须极其谨慎。对于加固系统，如果它们旨在成为离线环境，则必须强制执行允许相互通信的受信任系统边界，因此任何钩子（系统、Web 或文件）都只能与那些受信任的系统通信。强烈建议对通过系统钩子进行的通信使用 TLS。

## 推送规则

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **推送规则**。

确保选中以下项目：

- **拒绝未验证的用户**
- **不允许用户使用 `git push` 删除 Git 标签**
- **检查提交作者是否为 GitLab 用户**
- **防止推送密钥文件**

这些调整有助于将推送限制为已建立并获得授权的用户。

## 部署密钥

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **部署密钥**。

公共部署密钥用于授予对实例上**所有**项目的读取或读/写访问权限，旨在用于远程自动化访问项目。不应在加固环境中使用公共部署密钥。如果必须使用部署密钥，请改用项目部署密钥。更多信息，请参阅[部署密钥](../user/project/deploy_keys/_index.md)和[项目部署密钥](../user/project/deploy_keys/_index.md#create-a-project-deploy-key)的文档。

## 通用设置

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **设置** > **通用**。

可以在 4 个部分中进行加固调整。

### 可见性和访问控制

以下设置的默认值为 **私有**：

- **默认项目可见性**
- **默认代码片段可见性**
- **默认群组可见性**

只有被明确授予对特定项目、代码片段或群组访问权限的用户才能访问这些资源。这可以在以后根据需要或在其创建时进行调整。这有助于防止信息的意外或恶意泄露。

根据您的安全策略和态势，您可能希望将**限制可见性级别**设置为 **公开**，因为这会阻止未认证的用户查看用户资料。

在**导入源**中，仅选择您真正需要的源。

典型的部署会将**已启用的 Git 访问协议**设置为 **Both SSH and HTTP(S)**。但是，如果您的用户未使用其中一种 Git 协议，请相应地将其设置为 **Only SSH** 或 **Only HTTP(S)**。这有助于缩小攻击面。

对于 SSH 密钥类型，首选顺序为：`ED25519`（和 `ED25519-SK`）、`RSA` 和 `ECDSA`（和 `ECDSA-SK`）。当 `RSA` 设置为 2048 位或更高时，`ED25519` 被认为与 `RSA` 一样安全，但 `ED25519` 密钥更小，算法速度更快。

`ED25519-SK` 和 `ECDSA-SK` 都以 `-SK` 结尾，代表“安全密钥”。`-SK` 类型与 FIDO/U2F 标准兼容，适用于硬件令牌，例如 YubiKeys。

`DSA` 应设置为“被禁止”。`DSA` 存在已知缺陷，许多密码学家对使用 `ECDSA` 持怀疑态度且不支持使用。

如果极狐GitLab 处于 FIPS 模式，请使用以下设置：

- 如果在 FIPS 模式下运行：
  - 使用 `RSA`，设置为 **必须至少为 2048 位**。
  - 使用 `ECDSA`（和 `ECDSA-SK`），设置为 **必须至少为 256 位**。
  - 将所有其他密钥类型设置为 **被禁止**。
    `RSA` 和 `ECDSA` 均获批用于 FIPS。
- 如果未在 FIPS 模式下运行，您必须使用 `ED25519`，也可以使用 `RSA`：
  - 将 `ED25519`（和 `ED25519-SK`）设置为 **必须至少为 256 位**。
  - 如果使用 `RSA`，将其设置为 **必须至少为 2048 位**。
  - 将所有其他密钥类型设置为 **被禁止**。
- 如果您正在为一组新用户设置实例，请使用最大位数设置来定义您的用户 SSH 密钥策略，以增强安全性。

在加固环境中，通常不需要 RSS 订阅源，在**订阅源令牌**中，选中 **禁用订阅源令牌** 复选框。

如果您所有的用户都来自特定的 IP 地址，请使用**全局允许的 IP 范围**来明确仅允许这些地址。

有关**可见性和访问控制**的更多详细信息，请参阅[可见性和访问控制](../administration/settings/visibility_and_access_controls.md)。有关 SSH 设置的信息，请参阅[SSH 密钥限制](ssh_keys_restrictions.md)。

### 账户和限制

出于加固目的，请确保未选中 **Gravatar 已启用** 旁边的复选框。应减少所有无关的通信，并且在某些环境中可能会受到限制。账户头像可以由用户手动上传。

此部分中的设置旨在帮助对您的用户强制执行您自己特定标准的自定义实现。由于各种情况太多且差异太大，您应该查看[账户和限制设置文档](../administration/settings/account_and_limit_settings.md)并应用更改以强制执行您自己的策略。

### 新账户限制

确保无法在您的加固实例上创建新的用户账户，方法是确保清除 **允许新用户账户** 复选框。

在**电子邮件确认设置**中，确保选择了 **强硬**。现在，在授予访问权限之前，会强制执行用户对其电子邮件地址的验证。

**最小密码长度（字符数）** 默认设置为 12，只要使用额外的认证技术，这应该没问题。密码应该是复杂的，因此请确保选中所有这四个复选框：

- **要求数字**
- **要求大写字母**
- **要求小写字母**
- **要求符号**

如果您的所有用户都属于使用特定电子邮件域的组织，请在**新用户允许的域**中列出该域。这可以防止在其他域中拥有电子邮件地址的人注册。

更多详细信息，请参阅[新用户账户限制](../administration/settings/sign_up_restrictions.md)。

### 登录限制

应为所有用户启用双因素认证 (2FA)。确保选中 **双因素认证** (2FA) 旁边的复选框。

**双因素认证宽限期** 的默认设置为 48 小时。应将其调整为更短的时间，例如 8 小时。

确保选中 **启用管理员模式** 旁边的复选框，以便 **管理员模式** 处于活动状态。这要求具有管理员访问权限的用户必须使用额外的认证才能执行管理任务，从而强制执行用户的额外 2FA。

在**未知登录的电子邮件通知**中，确保选中 **启用电子邮件通知**。当从无法识别的位置发生登录时，这会向用户发送一封电子邮件。

更多详细信息，请参阅[登录限制](../administration/settings/sign_in_restrictions.md)。

## 集成

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **设置** > **集成**。

通常，只要管理员控制和监控使用情况，集成在加固环境中是可以的。对于允许来自外部系统的操作触发通常需要一定访问级别的动作和流程的集成，请保持谨慎，如果由本地进程或经过身份验证的用户执行，您通常会限制或审计这些动作和流程。

## 指标和分析

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **设置** > **指标和分析**。

加固的主要重点是**使用情况统计**：

- 您应该确保选中 **启用版本检查**。这会检查您是否正在运行最新版本的极狐GitLab，并且由于新版本和新功能及安全补丁频繁发布，这有助于您保持最新状态。
- 如果您的环境是隔离的，或者您的组织要求限制数据收集和统计报告给软件供应商，您可能必须关闭 **启用服务 ping** 功能。

## 网络

1. 在右上角，选择 **管理员**。
1. 在左侧边栏中，选择 **设置** > **网络**。

对于任何启用速率限制的设置，请确保它已被选中。默认值应该没问题。此外，还有许多启用访问的设置，所有这些设置都应被清除。

在您做出这些调整后，您可以微调系统以满足性能和用户需求，这可能需要禁用和调整速率限制或启用访问。以下是一些需要注意的事项：

- 在**出站请求**中，如果您需要开放对有限数量系统的访问，可以通过指定 IP 地址或主机名来限制对这些系统的访问。同样在本节中，如果您允许任何访问，请确保您已选中**强制执行 DNS 重绑定攻击保护**。

- 在**评论速率限制**和**用户 API 速率限制**下，如果需要，您可以将特定用户从这些限制中排除。
