通用加固指南在[主要加固文档](hardening.md)中概述。

以下文档总结了极狐GitLab 实例加固的一些底层理念。在许多情况下，它们实际上适用于所有计算机系统。

<a id="layered-security"></a>

## 分层安全

如果实现安全有两种方式，那么两种方式都应实施，而不是只实施其中一种。一个简单的例子是账号安全：

- 为账号使用长、复杂且唯一的密码。
- 为认证过程实施第二因素以增强安全性。
- 使用硬件令牌作为第二因素。
- 在认证尝试失败后锁定账号（至少锁定一段固定时间）。
- 在特定时间段内未使用的账号应被禁用。通过自动化或定期审计来强制执行这一点。

不要只使用列表中的一项或两项，而应尽可能多地使用。这一理念除了账号安全之外还可以应用于其他领域——应尽可能应用于每个领域。

<a id="eliminate-security-through-obscurity"></a>

## 消除隐蔽式安全

隐蔽式安全是指，因为担心潜在攻击者可能利用某些细节来策划攻击，而不讨论系统、服务或流程的某些要素。相反，系统应加固到这样的程度：即使其配置细节公开，系统仍能保持尽可能高的安全性。本质上，如果攻击者了解了计算机系统配置的细节，也不会给他们带来任何优势。隐蔽式安全的缺点之一是，它可能导致系统管理员产生一种潜在的错误安全感，认为系统比实际更安全。

这方面的一个例子是在非标准 TCP 端口上运行服务。例如，服务器上默认的 SSH 守护进程端口是 TCP 端口 22，但可以将 SSH 守护进程配置为在其他端口上运行，例如 TCP 端口 2222。配置了此设置的管理员可能认为这提高了系统的安全性。然而，攻击者通常会对系统进行端口扫描以发现所有开放端口，从而能够快速发现 SSH 服务，并消除任何感知到的安全优势。

由于极狐GitLab 是一个开放核心系统，且所有配置选项都有完善的文档记录并属于公开信息，隐蔽式安全的理念与极狐GitLab 的核心价值观——透明——相悖。这些加固建议旨在公开，以帮助消除任何隐蔽式安全。

<a id="attack-surface-reduction"></a>

## 攻击面缩减

极狐GitLab 是一个包含许多组件的大型系统。作为一般安全规则，禁用未使用的系统会有所帮助。这可以消除潜在攻击者可用于发起攻击的可用“攻击面”。这还可能带来增加可用系统资源的额外优势。

例如，系统上有一个进程每五分钟启动一次并检查队列中的输入，在执行检查时查询多个子进程。如果您不使用该进程，就没有理由配置它，应将其禁用。如果攻击者找到了利用该进程的攻击途径，即使您的组织并未使用它，攻击者也可能利用它。作为一般规则，您应禁用任何未使用的服务。

<a id="external-systems"></a>

## 外部系统

在规模更大但仍经过加固的部署中，通常会使用多个节点来处理极狐GitLab 部署所需的负载。在这些情况下，请结合使用外部、操作系统和配置选项来设置防火墙规则。任何使用限制的选项都应仅开放到足以让子系统正常运行的程度。只要有可能，就为网络流量使用 TLS 加密。
