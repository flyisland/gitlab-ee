通用加固指南在[主要加固文档](hardening.md)中有概述。

以下文档总结了极狐GitLab 实例加固的一些基本理念。
在许多情况下，它们实际上适用于所有计算机系统。

<a id="layered-security"></a>

## 分层安全

如果有两种实现安全的方法，那么应该同时实施这两种方法，而不是只实施一种。
一个简单的例子是账户安全：

- 为账户使用一个长、复杂且唯一的密码。
- 在认证过程中实施第二因素以增加安全性。
- 使用硬件令牌作为第二因素。
- 对于失败的认证尝试，锁定账户（至少固定一段时间）。
- 对于在特定时间段内未使用的账户应禁用，通过自动化或定期审计来强制执行。

与其只使用列表中的一两个项目，不如尽可能多地使用。这一理念不仅适用于账户安全，还应适用于所有可能的领域。

<a id="eliminate-security-through-obscurity"></a>

## 消除通过隐匿实现的安全

通过隐匿实现的安全意味着，由于担心潜在攻击者可能利用这些细节来策划攻击，因此不讨论系统、服务或流程的某些元素。
相反，系统应该被保护到即使其配置细节公开，系统仍然尽可能安全的程度。
本质上，如果攻击者了解了计算机系统配置的细节，这不会给他们带来优势。
通过隐匿实现的安全的一个缺点是，它可能导致系统管理员产生潜在的错误安全感，认为系统比实际更安全。

一个例子是在非标准 TCP 端口上运行服务。例如，服务器上默认的 SSH 守护进程端口是 TCP 端口 22，但可以将 SSH 守护进程配置为在另一个端口（如 TCP 端口 2222）上运行。
配置此设置的管理员可能认为这增加了系统的安全性，然而攻击者通常会通过端口扫描系统来发现所有开放端口，从而快速发现 SSH 服务，消除任何感知到的安全优势。

由于极狐GitLab 是一个开放核心系统，所有配置选项都有详细文档和公开信息，通过隐匿实现的安全理念与极狐GitLab 的核心价值观——透明度相悖。
这些加固建议旨在公开，以帮助消除任何通过隐匿实现的安全。

<a id="attack-surface-reduction"></a>

## 减少攻击面

极狐GitLab 是一个包含许多组件的大型系统。作为安全的一般规则，禁用未使用的系统会有所帮助。
这消除了潜在攻击者可用来攻击的“攻击面”。
这还有增加可用系统资源的额外好处。

例如，系统上有一个进程每五分钟启动一次并检查输入队列，在执行检查时查询多个子进程。
如果你不使用该进程，就没有理由配置它，应该将其禁用。
如果攻击者发现了利用此进程的攻击向量，即使你的组织不使用它，攻击者也可能会利用它。
作为一般规则，你应该禁用任何未使用的服务。

<a id="external-systems"></a>

## 外部系统

在较大但仍然加固的部署中，通常会使用多个节点来处理极狐GitLab 部署所需的负载。
在这些情况下，结合使用外部、操作系统和配置选项来设置防火墙规则。
任何使用限制的选项只应开放到足以让子系统正常运行的程度。
尽可能对网络流量使用 TLS 加密。
