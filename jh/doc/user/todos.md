您的*待办事项列表*是一个按时间顺序排列、等待您处理的事项列表。
这些事项被称为*待办事项*。

您可以使用待办事项列表追踪与您在极狐GitLab 中所做工作相关的操作。当有人联系您或需要您关注时，待办事项便会出现在您的待办事项列表中。

<a id="access-the-to-do-list"></a>

## 访问待办事项列表

要访问您的待办事项列表：

在右上角，选择 **待办事项** ({{< icon name="task-done" >}})。

<a id="filter-the-to-do-list"></a>

### 过滤待办事项列表

要过滤您的待办事项列表：

1. 在列表上方，将光标置于文本框中。
1. 选择一个预定义的过滤器。
1. 按 <kbd>Enter</kbd> 键。

<a id="sort-the-to-do-list"></a>

### 排序待办事项列表

要排序待办事项列表：

1. 在 **待办** 标签页中，从右上角的选项中选择：

   - **推荐** 按创建日期和先前暂停日期的组合排序，已暂停的事项会排在最前面。
   - **已更新** 按事项最近更新的日期排序。
   - **标签优先级** 按[您设置的优先级](project/labels.md#set-label-priority)排序。

1. 可选。选择排序方向。

> [!note]
> 在 **已暂停** 和 **已完成** 标签页中，**推荐** 排序仅按事项的创建日期排序。

<a id="actions-that-create-to-do-items"></a>

## 产生待办事项的操作

{{< history >}}

- 在极狐GitLab 13.8 中引入，[带有一个功能标志](../administration/feature_flags/_index.md)名为 `multiple_todos`。默认禁用。
- 成员访问请求通知在极狐GitLab 15.8 中引入。
- 多个待办事项功能在极狐GitLab 16.2 中于 JihuLab.com 启用。
- 多个待办事项功能在极狐GitLab 17.8 中于私有化部署版启用。功能标志 `multiple_todos` 默认启用。

{{< /history >}}

> [!flag]
> 此功能的可用性由功能标志控制。
> 更多信息，请参阅历史记录。

许多待办事项会自动创建。
一些会向您的待办事项列表添加待办事项的操作包括：

- 议题或合并请求被指派给您。
- 合并请求被请求由您审核。
- 您在议题、合并请求或史诗的描述或评论中被提及。
- 您在某次提交或设计的评论中被提及。
- 您的合并请求的 CI/CD 流水线失败。
- 一个打开的合并请求因冲突而无法合并，并且以下任一情况成立：
  - 您是作者。
  - 您是设置该合并请求在流水线成功后自动合并的用户。
- 合并请求从[合并队列](../ci/pipelines/merge_trains.md)中被移除，而您是将其添加进去的用户。
- 由您所有的群组或项目发起了成员访问请求。

在极狐GitLab 17.8 及更高版本中，每当有人提及您，即使是同一个议题或合并请求中，您都会收到一个新的待办通知。

对于其他创建待办事项的操作，如指派或审核请求，
即使该操作在同一个议题或合并请求中多次发生，您也只会收到每个操作类型的一个通知。

待办事项不受[极狐GitLab 邮件通知设置](profile/notifications.md)的影响。
唯一的例外：如果您的通知设置设为 **自定义** 且勾选了 **创建您可以批准的合并请求时**，
当您有资格批准某个合并请求时，您会收到一个待办事项。

<a id="create-a-to-do-item"></a>

## 创建待办事项

{{< history >}}

- 在极狐GitLab 16.0 中于目标、关键结果和任务中引入。

{{< /history >}}

您可以手动将事项添加到待办事项列表中。

1. 前往您的：

   - 议题
   - 合并请求
   - 史诗
   - 设计
   - 事件
   - 目标或关键结果
   - 任务

1. 在右上角，选择 **添加待办事项** ({{< icon name="todo-add" >}})。

<a id="create-a-to-do-item-by-mentioning-someone"></a>

### 通过提及某人创建待办事项

您可以通过在除代码块外的任何地方提及某人来创建待办事项。在同一条消息中多次提及同一用户只会创建一个待办事项。

例如，在下面的评论中，除了 `frank` 之外，每个人都会收到一个为他们创建的待办事项：

````markdown
@alice 你觉得怎么样？抄送：@bob

- @carol 你能看看吗？

> @dan 你怎么看？

嘿 @erin，他们是这么说的：

```
嗨，请给 @frank 发消息 :incoming_envelope:
```
````

<a id="actions-that-mark-a-to-do-item-as-done"></a>

## 将待办事项标记为已完成的操作

对生成待办事项的对象（例如议题、合并请求或史诗）采取的各种操作，会将其对应的待办事项标记为已完成。

在以下情况下，待办事项会被标记为已完成：

- 对描述或评论添加表情反应。
- 添加或移除标签。
- 更改指派人。
- 更改里程碑。
- 关闭该待办事项关联的对象。
- 创建一个评论。
- 编辑描述。
- 解决设计讨论串。
- 接受或拒绝项目或群组成员资格请求。

在以下情况下，待办事项**不**会被标记为已完成：

- 添加关联事项（如关联议题）。
- 添加子事项（如子史诗或任务）。
- 添加时间跟踪。
- 将自己设为指派人。
- 更改议题的健康状态。

如果其他人关闭了议题或史诗，或对其采取了操作，您的待办事项仍将保持待处理状态。

当合并请求被合并或关闭时，所有被指派、被请求审核、被要求批准或被添加为批准者的用户的待办事项都会被标记为已完成。

<a id="mark-a-to-do-item-as-done"></a>

## 将待办事项标记为已完成

您可以手动将待办事项标记为已完成。

有两种方法可以做到：

- 在待办事项列表中，在待办事项的右侧，选择 **标记为已完成** ({{< icon name="check" >}}）。
- 在资源（例如议题或合并请求）的右上角，选择 **标记为已完成** ({{< icon name="todo-done" >}}）。

<a id="re-add-a-done-to-do-item"></a>

## 重新添加已完成的待办事项

如果您误将一个待办事项标记为已完成，可以从 **已完成** 标签页中重新添加它：

1. 在右上角，选择 **待办事项** ({{< icon name="task-done" >}}）。
1. 在顶部，选择 **已完成**。
1. 找到您想重新添加的待办事项。
1. 在此待办事项旁边，选择 **撤销** {{< icon name="redo" >}}。

该待办事项现在会显示在待办事项列表的 **待办** 标签页中。

<a id="snooze-to-do-items"></a>

## 暂停待办事项

{{< history >}}

- 在极狐GitLab 17.9 中引入。

{{< /history >}}

您可以暂停待办事项，将其暂时从主待办事项列表中隐藏。这可以让您专注于更紧急的任务，并在稍后返回处理已暂停的事项。

要暂停一个待办事项：

1. 在您的待办事项列表中，在您想暂停的待办事项旁边，选择暂停 ({{< icon name="clock" >}}）。
1. 如果您希望将待办事项暂停至特定的时间和日期，请选择
   `直到特定的时间和日期` 选项。否则，请选择一个预设的暂停时长：
   - 一个小时
   - 直到今天晚些时候（4 小时后）
   - 直到明天（明天上午 8 点本地时间）

已暂停的待办事项将从您的主待办事项列表中移除，并显示在单独的 **已暂停** 标签页中。

当暂停期结束时，该待办事项会自动返回您的主待办事项列表。它会附带一个指示器，显示其最初创建的时间。

<a id="view-snoozed-to-do-items"></a>

## 查看已暂停的待办事项

{{< history >}}

- 在极狐GitLab 17.9 中引入。

{{< /history >}}

要查看或管理您已暂停的待办事项：

1. 前往您的待办事项列表。
1. 在列表顶部，选择已暂停标签页。

从已暂停标签页，您可以：

- 查看某个已暂停的待办事项计划何时返回您的主列表。
- 移除暂停，使其立即返回主待办事项列表。
- 将一个已暂停的待办事项标记为已完成。

<a id="bulk-edit-to-do-items"></a>

## 批量编辑待办事项

{{< history >}}

- 在极狐GitLab 17.10 中引入。

{{< /history >}}

您可以批量编辑您的待办事项：

- 在 **待办** 标签页：将待办事项标记为已完成或暂停它们。
- 在 **已暂停** 标签页：将待办事项标记为已完成或移除它们。
- 在 **已完成** 标签页：恢复待办事项。

要批量编辑待办事项：

1. 在您的待办事项列表中：
   - 要选择个别事项，请勾选您要编辑的每个事项左侧的复选框。
   - 要选择页面上的所有事项，请勾选左上角的 **全选** 复选框。
1. 在右上角，选择所需的操作。

<a id="how-a-users-to-do-list-is-affected-when-their-access-changes"></a>

## 当用户权限变更时其待办事项列表会受到的影响

出于安全原因，当用户不再有权访问相关资源时，极狐GitLab 会删除对应的待办事项。
例如，如果用户不再有权访问某个议题、合并请求、史诗、项目或群组，
极狐GitLab 会删除相关的待办事项。

这个过程会在其权限变更后的一小时内发生。延迟删除是为了
防止数据丢失，以防用户的访问权限被意外撤销。
