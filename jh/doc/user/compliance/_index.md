面向用户的极狐GitLab 合规功能可确保您的极狐GitLab 群组和项目符合常见的合规标准。

<a id="compliant-workflow-automation"></a>

## 合规工作流自动化

对于合规团队而言，不仅要确信其控制措施和要求已正确设置，还要确信它们能持续保持正确设置，这一点非常重要。一种做法是定期手动检查设置，但这种方式容易出错且耗时。更好的方法是使用单一可信来源的设置和自动化，确保合规团队配置的内容始终保持配置状态并正常运行。以下功能可帮助您实现合规自动化：

| 功能                                                                                                                                  | 实例                            | 群组                               | 项目                             | 描述 |
|:-----------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [合规框架](compliance_frameworks/_index.md)                                                                      | {{< no >}} | {{< yes >}} | {{< no >}} | 描述项目必须遵循的合规要求类型。 |
| [合规流水线](compliance_pipelines.md)                                                                                 | {{< no >}} | {{< yes >}} | {{< no >}} | 为具有指定合规框架的任何项目定义要运行的流水线配置。 |
| [合并请求审批策略审批设置](../application_security/policies/merge_request_approval_policies.md#approval_settings) | {{< yes >}} | {{< yes >}} | {{< yes >}} | 强制执行合并请求审批策略，要求多个审批人，并覆盖极狐GitLab 实例或群组中所有已强制执行的群组或项目中的各种项目设置。 |

<a id="audit-management"></a>

## 审计管理

任何合规计划的一个重要组成部分，是能够回溯并了解发生了什么、何时发生以及由谁负责。您可以在审计场景中使用这一点，也可以在问题发生时用于了解其根本原因。

同时拥有底层、原始的审计数据列表以及高层、汇总的审计数据列表会很有帮助。借助这两者，合规团队可以快速判断是否存在问题，然后深入查看这些问题的具体细节。以下功能可帮助您了解极狐GitLab 中的情况并审计正在发生的事情：

| 功能                                           | 实例                            | 群组                               | 项目                             | 描述 |
|:--------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [审计事件](audit_events.md)                   | {{< yes >}} | {{< yes >}} | {{< yes >}} | 为维护代码的完整性，审计事件让管理员能够在高级审计事件系统中查看极狐GitLab 服务器中所做的任何修改，以便您控制、分析和跟踪每一次变更。 |
| [审计报告](audit_events.md)                  | {{< yes >}} | {{< yes >}} | {{< yes >}} | 根据已发生的审计事件创建并访问报告。使用极狐GitLab 预置报告或 API 构建您自己的报告。 |
| [审计事件流](audit_event_streaming.md) | {{< yes >}} | {{< yes >}} | {{< yes >}} | 将极狐GitLab 审计事件流式传输到 HTTP 端点或第三方服务，例如 AWS S3 或 GCP Logging。 |
| [合规中心](compliance_center/_index.md)  | {{< no >}} | {{< yes >}} | {{< yes >}} | 通过合规标准遵循情况报告和违规报告，快速了解您组织的合规状况。集中管理您群组的合规框架。 |

<a id="policy-management"></a>

## 策略管理

组织有独特的策略要求，这些要求可能来自组织标准，也可能来自监管机构的强制规定。以下功能可帮助您定义规则和策略，以遵循工作流要求、职责分离和安全供应链最佳实践：

| 功能                                                                                                                                                                                                                                                                | 实例                            | 群组                               | 项目                             | 描述 |
|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [精细用户角色<br/>和灵活权限](../permissions.md)                                                                                                                                                                                                  | {{< yes >}} | {{< yes >}} | {{< yes >}} | 通过五种不同的用户角色和外部用户设置来管理访问和权限。根据人员的角色设置权限，而不是对代码仓库的读或写访问权限。不要与只需要访问议题跟踪器的人员共享源代码。 |
| [合并请求审批](../project/merge_requests/approvals/_index.md)                                                                                                                                                                                               | {{< yes >}} | {{< yes >}} | {{< yes >}} | 配置合并请求所需的审批。 |
| [推送规则](../project/repository/push_rules.md)                                                                                                                                                                                                                      | {{< yes >}} | {{< yes >}} | {{< yes >}} | 控制对您代码仓库的推送。 |
| 使用<br/>[受保护分支](../project/repository/branches/protected.md#require-code-owner-approval)和<br/>[自定义 CI/CD 配置路径](../../ci/pipelines/settings.md#specify-a-custom-cicd-configuration-file)实现职责分离 | {{< no >}} | {{< no >}} | {{< yes >}} | 利用极狐GitLab 跨项目 YAML 配置来定义代码部署者和代码开发者。了解如何使用此设置来定义这些角色，请参见[职责分离部署项目](https://gitlab.com/guided-explorations/separation-of-duties-deploy/blob/master/README.md)和[职责分离项目](https://gitlab.com/guided-explorations/separation-of-duties/blob/master/README.md)。 |
| [安全策略](../application_security/policies/_index.md)                                                                                                                                                                                                        | {{< yes >}} | {{< yes >}} | {{< yes >}} | 配置可自定义的策略，这些策略要求根据策略规则进行合并请求审批，或为满足合规要求强制安全扫描器在项目流水线中执行。策略可以针对特定项目精细强制执行，也可以针对群组或子群组中的所有项目强制执行。 |
