这些 CI/CD 变量特定于基于浏览器的 DAST 分析器。您可以使用它们根据自身需求自定义 DAST 的行为。

<a id="scanner-behavior"></a>

## 扫描器行为

这些变量控制扫描的执行方式以及扫描结果的存储位置。

| CI/CD 变量 | 类型 | 示例 | 描述 |
| :------------- | :--- | ------- | :---------- |
| `DAST_CHECKS_TO_EXCLUDE` | string | `552.2,78.1` | 要从扫描中排除的检查标识符的逗号分隔列表。有关标识符，请参阅[漏洞检查](../checks/_index.md)。 |
| `DAST_CHECKS_TO_RUN` | List of strings | `16.1,16.2,16.3` | 要用于扫描的检查标识符的逗号分隔列表。有关标识符，请参阅[漏洞检查](../checks/_index.md)。 |
| `DAST_CRAWL_GRAPH` | boolean | `true` | 设置为 `true` 可生成扫描爬取阶段所访问导航路径的 SVG 图。您还必须将 `gl-dast-crawl-graph.svg` 定义为 CI 作业产物，才能访问生成的图。默认为 `false`。 |
| `DAST_FULL_SCAN` | boolean | `true` | 设置为 `true` 可同时运行被动检查和主动检查。默认为 `false`。 |
| `DAST_LOG_BROWSER_OUTPUT` | boolean | `true` | 设置为 `true` 可记录 Chromium 的 `STDOUT` 和 `STDERR`。 |
| `DAST_LOG_CONFIG` | List of strings | `brows:debug,auth:debug` | （已弃用）用于控制台日志的模块列表及其预期日志级别。 |
| `DAST_LOG_DEVTOOLS_CONFIG` | string | `Default:messageAndBody,truncate:2000` | 设置为记录 DAST 与 Chromium 浏览器之间的协议消息。 |
| `DAST_LOG_FILE_CONFIG` | List of strings | `brows:debug,auth:debug` | 用于文件日志的模块列表及其预期日志级别。 |
| `DAST_LOG_FILE_PATH` | string | `/output/browserker.log` | 设置为文件日志的路径。默认为 `gl-dast-scan.log`。 |
| `SECURE_ANALYZERS_PREFIX` | URL | `registry.organization.com` | 设置用于下载分析器的 Docker 镜像仓库基础地址。 |
| `SECURE_LOG_LEVEL` | string | `debug` | 设置文件日志的默认级别。请参阅 [SECURE_LOG_LEVEL](../troubleshooting.md#secure_log_level)。 |

<a id="elements-actions-and-timeouts"></a>

## 元素、操作和超时

这些变量告诉扫描器在何处查找特定元素、执行哪些操作，以及等待操作完成的时间。

| CI/CD 变量 | 类型 | 示例 | 描述 |
| :------------- | :--- | ------- | :---------- |
| `DAST_ACTIVE_SCAN_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `3h` | 等待扫描的主动扫描阶段完成的最长时间。默认为 3h。 |
| `DAST_ACTIVE_SCAN_WORKER_COUNT` | number | `3` | 并行运行的主动检查数量。默认为 3。 |
| `DAST_CRAWL_MAX_ACTIONS` | number | `10000` | 爬取器执行的最大操作数。操作示例包括选择链接或填写表单。默认为 `10000`。 |
| `DAST_CRAWL_MAX_DEPTH` | number | `10` | 爬取器执行的最大链式操作数。例如，`Click, Form Fill, Click`的深度为三。默认为 `10`。 |
| `DAST_CRAWL_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `5m` | 等待扫描的爬取阶段完成的最长时间。默认为 `24h`。 |
| `DAST_CRAWL_WORKER_COUNT` | number | `3` | 可使用的最大并发浏览器实例数。对于 JihuLab.com 上的实例 runner，建议最多使用三个。资源更多的私有 runner 可能从更高的数值中获益，但超过五到七个实例后收益可能很小。默认值是动态的，等于可用的逻辑 CPU 数量。 |
| `DAST_PAGE_DOM_READY_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `7s` | 导航完成后，等待浏览器认为页面已加载并可供分析的最长时间。默认为 `6s`。 |
| `DAST_PAGE_DOM_STABLE_WAIT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `200ms` | 定义在检查页面是否稳定之前等待 DOM 更新的时长。默认为 `500ms`。 |
| `DAST_PAGE_ELEMENT_READY_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `600ms` | 在确定元素可供分析之前等待该元素的最长时间。默认为 `300ms`。 |
| `DAST_PAGE_IS_LOADING_ELEMENT` | [选择器](authentication.md#finding-an-elements-selector) | `css:#page-is-loading` | 当该选择器在页面上不再可见时，向分析器表明页面已加载完成，扫描可以继续。不能与 `DAST_PAGE_IS_READY_ELEMENT` 一起使用。 |
| `DAST_PAGE_IS_READY_ELEMENT` | [选择器](authentication.md#finding-an-elements-selector) | `css:#page-is-ready` | 当检测到该选择器在页面上可见时，向分析器表明页面已加载完成，扫描可以继续。不能与 `DAST_PAGE_IS_LOADING_ELEMENT` 一起使用。 |
| `DAST_PAGE_MAX_RESPONSE_SIZE_MB` | number | `15` | HTTP 响应正文的最大大小。正文大于此值的响应会被浏览器阻止。默认为 `10` MB。 |
| `DAST_PAGE_READY_AFTER_ACTION_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `7s` | 等待浏览器认为页面已加载并可供分析的最长时间。默认为 `7s`。 |
| `DAST_PAGE_READY_AFTER_NAVIGATION_TIMEOUT` | [时长字符串](https://pkg.go.dev/time#ParseDuration) | `15s` | 等待浏览器从一个页面导航到另一个页面的最长时间。默认为 `15s`。 |
| `DAST_PASSIVE_SCAN_WORKER_COUNT` | int | `5` | 并行执行被动扫描的工作进程数量。默认为可用 CPU 数量。 |
| `DAST_PKCS12_CERTIFICATE_BASE64` | string | `ZGZkZ2p5NGd...` | 用于需要双向 TLS 的站点的 PKCS12 证书。必须编码为 base64 文本。 |
| `DAST_PKCS12_PASSWORD` | string | `password` | `DAST_PKCS12_CERTIFICATE_BASE64`中所用证书的密码。使用极狐GitLab UI 创建敏感的[自定义 CI/CD 变量](../../../../../ci/variables/_index.md#define-a-cicd-variable-in-the-ui)。 |
| `DAST_REQUEST_ADVERTISE_SCAN` | boolean | `true` | 设置为 `true` 可为每个发送的请求添加 `Via: GitLab DAST <version>` 请求头，表明该请求是作为极狐GitLab DAST 扫描的一部分发送的。默认值：`false`。 |
| `DAST_REQUEST_COOKIES` | dictionary | `abtesting_group:3,region:locked` | 要添加到每个请求的 cookie 名称和值。 |
| `DAST_REQUEST_HEADERS` | String | `Cache-control:no-cache` | 设置为请求头名称和值的逗号分隔列表。不支持以下请求头：`content-length`、`cookie2`、`keep-alive`、`hosts`、`trailer`、`transfer-encoding`，以及所有带 `proxy-` 前缀的请求头。 |
| `DAST_REQUEST_USER_AGENT` | String |  | 设置为更改浏览器发送的 user-agent 字符串。默认 user-agent 为 Linux 上的 Google Chrome。 |
| `DAST_SCOPE_ALLOW_HOSTS` | List of strings | `site.com,another.com` | 此变量中包含的主机名在爬取时被视为在范围内。默认情况下，`DAST_TARGET_URL`的主机名包含在允许的主机列表中。使用 `DAST_REQUEST_HEADERS` 设置的请求头会添加到向这些主机名发出的每个请求中。 |
| `DAST_SCOPE_EXCLUDE_ELEMENTS` | [选择器](authentication.md#finding-an-elements-selector) | `a[href='2.html'],css:.no-follow` | 扫描时忽略的选择器的逗号分隔列表。 |
| `DAST_SCOPE_EXCLUDE_HOSTS` | List of strings | `site.com,another.com` | 此变量中包含的主机名被视为排除在外，连接会被强制断开。 |
| `DAST_SCOPE_IGNORE_HOSTS` | List of strings | `site.com,another.com` | 此变量中包含的主机名会被访问，但不会受到攻击，也不会针对其进行报告。 |
| `DAST_TARGET_CHECK_SKIP` | boolean | `true` | 设置为 `true` 可阻止 DAST 在扫描前检查目标是否可用。默认值：`false`。 |
| `DAST_TARGET_CHECK_TIMEOUT` | number | `60` | 等待目标可用的时间限制（秒）。默认值：`60s`。 |
| `DAST_TARGET_PATHS_FILE` | string | `/builds/project/urls.txt` | 仅扫描这些路径，而不是爬取整个站点。设置为包含相对于 `DAST_TARGET_URL`的 URL 路径列表的文件路径。该文件必须是纯文本，每行一个路径。设置此项后，`DAST_CRAWL_MAX_DEPTH` 默认为 1。要阻止此行为，请设置 `DAST_OVERRIDE_MAX_DEPTH: false`。 |
| `DAST_TARGET_PATHS` | string | `/page1.html,/category1/page3.html` | 仅扫描这些路径，而不是爬取整个站点。设置为相对于 `DAST_TARGET_URL`的 URL 路径的逗号分隔列表。设置此项后，`DAST_CRAWL_MAX_DEPTH` 默认为 1。要阻止此行为，请设置 `DAST_OVERRIDE_MAX_DEPTH: false`。 |
| `DAST_TARGET_PROXY` | URL | `http://proxy.example.com:8080` | DAST 扫描器的上游 HTTP 代理 URL。 |
| `DAST_TARGET_URL` | URL | `https://site.com` | 要扫描的网站 URL。 |
| `DAST_USE_CACHE` | boolean | `true` | 设置为 `false` 可禁用缓存。默认值：`true`。**注意**：禁用缓存可能导致 OOM 事件或 DAST 作业超时。 |
| `DAST_CRAWL_GROUPED_URLS` | string | `https://example.com/hello/*,https://example.com/world/*/details` | （实验）设置为通配符 URL 模式的逗号分隔列表，其中至少包含一个 `*`。为缩短扫描时间，扫描器会按模式分组，并且每个模式只分析一个匹配的 URL。 |

<a id="authentication"></a>

### 身份验证

这些变量告诉扫描器如何向您的应用程序进行身份验证。

| CI/CD 变量 | 类型 | 示例 | 描述 |
| :------------- | :--- | ------- | :---------- |
| `DAST_AUTH_AFTER_LOGIN_ACTIONS` | string | `select(option=id:accept-yes),click(on=css:.continue)` | 登录后但在登录验证之前要执行的操作的逗号分隔列表。支持 `click` 和 `select` 操作。请参阅[提交登录表单后执行其他操作](authentication.md#taking-additional-actions-after-submitting-the-login-form)。 |
| `DAST_AUTH_BEFORE_LOGIN_ACTIONS` | [选择器](authentication.md#finding-an-elements-selector) | `css:.user,id:show-login-form` | 表示在将 DAST_AUTH_USERNAME 和 DAST_AUTH_PASSWORD 输入登录表单之前要点击的元素的逗号分隔选择器列表。 |
| `DAST_AUTH_CLEAR_INPUT_FIELDS` | boolean | `true` | 在尝试手动登录之前禁用清除用户名和密码字段。默认设置为 false。 |
| `DAST_AUTH_COOKIE_NAMES` | string | `sessionID,groupName` | 设置为 cookie 名称的逗号分隔列表，以指定哪些 cookie 用于身份验证。 |
| `DAST_AUTH_FIRST_SUBMIT_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | 用于定位多页登录流程中点击以提交用户名表单的元素的选择器。 |
| `DAST_AUTH_NEGOTIATE_DELEGATION` | string | `*.example.com,example.com,*.EXAMPLE.COM,EXAMPLE.COM` | 允许用于集成身份验证和委派的服务器。此属性设置两个 Chromium 策略：[AuthServerAllowlist](https://chromeenterprise.google/policies/#AuthServerAllowlist) 和 [AuthNegotiateDelegateAllowlist](https://chromeenterprise.google/policies/#AuthNegotiateDelegateAllowlist)。[引入](https://gitlab.com/gitlab-org/gitlab/-/issues/502476)于极狐GitLab 17.6。 |
| `DAST_AUTH_OTP_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `name:otp` | 描述登录表单上用于输入一次性密码的元素的选择器。 |
| `DAST_AUTH_OTP_KEY` | String | `I5UXITDBMIQEIQKTKQFA====` | 生成用于向网站进行身份验证的一次性密码时使用的 Base32 编码密钥。 |
| `DAST_AUTH_OTP_SUBMIT_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | 用于定位点击以提交 OTP 表单的元素的选择器，适用于 OTP 表单与用户名表单分开的情况。 |
| `DAST_AUTH_PASSWORD` | String | `P@55w0rd!` | 用于向网站进行身份验证的密码。 |
| `DAST_AUTH_PASSWORD_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `name:password` | 描述登录表单上用于输入密码的元素的选择器。 |
| `DAST_AUTH_SUBMIT_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | 用于定位点击以提交表单的元素的选择器：单页登录时提交登录表单，多页登录时提交密码表单。 |
| `DAST_AUTH_SUCCESS_IF_AT_URL` | URL | `https://www.site.com/welcome*` | 与浏览器中的 URL 进行比较以确定提交登录表单后身份验证是否成功的 URL。可以使用通配符 `*` 来匹配动态 URL。 |
| `DAST_AUTH_SUCCESS_IF_ELEMENT_FOUND` | [选择器](authentication.md#finding-an-elements-selector) | `css:.user-avatar` | 描述一个元素的选择器，通过该元素是否存在来确定提交登录表单后身份验证是否成功。 |
| `DAST_AUTH_SUCCESS_IF_NO_LOGIN_FORM` | boolean | `true` | 通过检查提交登录表单后是否不存在登录表单来验证身份验证是否成功。此成功检查默认启用。 |
| `DAST_AUTH_TYPE` | string | `basic-digest` | 要使用的身份验证类型。 |
| `DAST_AUTH_URL` | URL | `https://www.site.com/login` | 目标网站上包含登录表单的页面 URL。DAST_AUTH_USERNAME 和 DAST_AUTH_PASSWORD 会随登录表单一起提交，以创建经过身份验证的扫描。 |
| `DAST_AUTH_USERNAME` | string | `user@email.com` | 用于向网站进行身份验证的用户名。 |
| `DAST_AUTH_USERNAME_FIELD` | [选择器](authentication.md#finding-an-elements-selector) | `name:username` | 描述登录表单上用于输入用户名的元素的选择器。 |
| `DAST_SCOPE_EXCLUDE_URLS` | URLs | `https://site.com/.*/sign-out` | 在经过身份验证的扫描期间要跳过的 URL；以逗号分隔。可以使用正则表达式语法来匹配多个 URL。例如，`.*` 匹配任意字符序列。 |
| `DAST_AUTH_REPORT` | boolean | `true` | 设置为 `true` 可生成详细说明身份验证过程中所执行步骤的报告。您还必须将 `gl-dast-debug-auth-report.html` 定义为 CI 作业产物，才能访问生成的报告。报告内容有助于调试身份验证失败。默认为 `false`。 |
