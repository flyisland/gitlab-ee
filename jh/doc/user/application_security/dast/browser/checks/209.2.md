<a id="generation-of-database-error-message-containing-sensitive-information"></a>

## 描述

应用程序被发现返回数据库错误消息。确定数据库类型可能帮助攻击者利用针对系统的 SQL 注入攻击。尽管调试消息在开发和调试期间很有帮助，但在发生错误时不应向用户呈现这些消息。

## 修复方案

应用程序应在内部处理数据库错误条件，并将已知故障类型映射为可向用户显示的错误代码。这些错误代码应为应用程序定制，并与相应的 HTTP 错误代码一起返回。

发生错误时，应用程序识别错误类型或类别，并向用户显示一个数值。请求也应被追踪，以便当用户看到错误代码时，它有对应的请求 ID。支持团队随后可以将 HTTP 错误、定制错误代码和日志文件中的请求 ID 关联起来，以确定错误的根本原因，而无需向最终用户泄露细节。

返回定制错误的示例：

```plaintext
HTTP/1.1 500 Internal Server Error
...
发生错误 [0004]，请联系支持或稍后重试您的请求。
Request ID [a4bc91def12]
...
```
