<a id="description"></a>

## 描述

应用程序未能通过使用安全的应用令牌或 `SameSite` cookie 指令来防范跨站请求伪造(CSRF)。

攻击者可利用此漏洞在第三方站点创建链接或表单，并诱骗已认证的受害者访问它们。

<a id="remediation"></a>

## 修复方案

考虑将所有会话 cookie 设置为 `SameSite=Strict` 属性。但需注意，这可能影响通过其他媒介分享链接的可用性。建议采用基于两个 cookie 的方法，如 RFC 中的[顶级导航](https://datatracker.ietf.org/doc/html/draft-ietf-httpbis-rfc6265bis-08#section-8.8.2)部分所述。

如果应用使用了通用框架，则反 CSRF 保护可能已内置但需要启用。请查阅应用框架文档了解详情。

如果以上选项都不适用，**强烈**建议使用第三方库。实现一个安全的反 CSRF 系统需要大量投入，且难以正确完成。
