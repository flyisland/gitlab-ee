<a id="description"></a>

## 描述

该应用程序未能通过使用安全的应用程序令牌或 `SameSite` Cookie 指令来防范跨站请求伪造（CSRF）。

攻击者可以通过在第三方网站上创建链接或表单，并诱骗已通过身份验证的受害者访问它们来利用此漏洞。

<a id="remediation"></a>

## 修复

考虑将所有会话 Cookie 设置为具有 `SameSite=Strict` 属性。但是，需要注意的是，在其他媒介之间共享链接时，这可能会影响可用性。建议采用基于两个 Cookie 的方法，如 RFC 的[顶层导航](https://datatracker.ietf.org/doc/html/draft-ietf-httpbis-rfc6265bis-08#section-8.8.2)部分所述。

如果应用程序使用通用框架，则可能内置了反 CSRF 保护，但需要启用。有关详细信息，请查阅您的应用程序框架文档。

如果这两种方法都不适用，**强烈**建议使用第三方库。实现安全的反 CSRF 系统是一项重大投入，且难以正确完成。
