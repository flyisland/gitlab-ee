<a id="description"></a>

## 描述

JavaScript 或 CSS 源文件从第三方域包含，没有使用
[子资源完整性 (SRI)](https://developer.mozilla.org/en-US/docs/Web/Security/Subresource_Integrity)。
如果攻击者攻陷了托管这些第三方资源的站点，他们可以注入恶意
脚本或 CSS 数据，试图危害你的应用程序的用户。然而，如果应用了 SRI 并且
攻击者试图修改脚本内容，浏览器将不会加载该脚本，你的
应用程序用户将受到保护免受恶意更改。

<a id="remediation"></a>

## 修复措施

所有已识别的资源应从与目标应用程序相同的域获取。如果这不可能，
强烈建议所有实现 `src` 值的 `script` 标签，或实现
`href` 值的 `link` 标签包含子资源完整性。要生成 SRI 完整性值，
可以使用 [SRI hash](https://www.srihash.org/) 工具，或运行以下命令之一：

- `cat FILENAME.js | openssl dgst -sha384 -binary | openssl base64 -A`
- `shasum -b -a 384 FILENAME.js | awk '{ print $1 }' | xxd -r -p | base64`

这些工具的输出必须添加为附加属性，特别是：`integrity` 和
`crossorigin=anonymous` 或 `crossorigin=use-credentials`。
下面是一个有效的受 SRI 保护的 script 标签示例：

```html
<script src="https://example.com/example-framework.js"
    integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
    crossorigin="anonymous"></script>
```
