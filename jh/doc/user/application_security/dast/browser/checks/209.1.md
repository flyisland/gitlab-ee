<a id="description"></a>

## 描述

发现应用程序会返回错误数据，如堆栈跟踪。根据错误消息中包含的数据，这些信息可能被攻击者用于实施进一步的攻击。虽然堆栈跟踪在开发和调试期间很有帮助，但在发生错误时不应将其呈现给用户。

<a id="remediation"></a>

## 补救措施

应用程序应在内部处理异常条件，并将已知的故障类型映射到可以显示给用户的错误代码。这些错误代码应根据应用程序进行定制，并与相关的 HTTP 错误代码一起返回。

当发生错误时，应用程序会识别错误类型或类别，并向用户显示一个数值。还应跟踪请求，以便在向用户显示错误代码时，具有相应的请求 ID。然后，支持团队可以在日志文件中关联 HTTP 错误、定制的错误代码和请求 ID，以确定错误的根本原因，而不会向最终用户泄露详细信息。

返回定制错误的示例：

```plaintext
HTTP/1.1 500 Internal Server Error
...
错误 [0004] 发生，请联系支持或稍后重试您的请求。
请求 ID [a4bc91def12]
...
```
