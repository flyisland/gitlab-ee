<a id="description"></a>

## 描述

跨站脚本（XSS）是一种攻击方式，它利用 Web 应用或系统将用户输入当作标记或脚本代码来处理。根据数据所使用的具体上下文对其进行编码非常重要。至少有六种上下文类型：

- HTML 标签内部：`<div>context 1</div>`
- 属性内部：```<div class="context 2"></div>```
- 事件属性内部：```<button onclick="context 3">button</button>```
- 脚本块内部：```<script>var x = "context 4"</script>```
- 不安全的元素 HTML 赋值：```element.innerHTML = "context 5"```
- URL 内部：```<iframe src="context 6"></iframe><a href="context 6">link</a>```

仅脚本块本身就可以通过多种方式进行编码。如果用户输入必须写在脚本标签之外，请务必谨慎。

<a id="remediation"></a>

## 修复

应用中显示的用户输入必须经过编码、清理或验证，以免被当作 HTML 处理或作为 JavaScript 代码执行。注意不要将服务器端模板与客户端模板混用，因为服务器端不会对 `{{ 7*7 }}` 这样的文本进行编码，而这可能会执行客户端功能。

不要在将用户输入插入数据存储之前对其进行编码。数据必须根据其输出上下文进行编码。强制显示系统处理编码要安全得多。

考虑使用框架内置的能力来自动编码用户输入。如果无法自动编码输入，请注意使用正确的输出编码。以下建议是尽力而为的方案，可能并非在所有情况下都适用。

- 在 HTML 标签内部（不包括 `script`）对以下内容进行编码：
  - `<` 编码为 `&lt;`
  - `>` 编码为 `&gt;`
  - `'` 编码为 `&apos;`
  - `"` 编码为 `&quot;`
  - `=` 编码为 `&#61;`
- 在属性内部（不包括事件属性）对以下内容进行编码：
  - `<` 编码为 `&lt;`
  - `>` 编码为 `&gt;`
  - `'` 编码为 `&apos;`
  - `"` 编码为 `&quot;`
  - `=` 编码为 `&#61;`
- 在事件属性、脚本块和不安全的 HTML 赋值中对以下内容进行编码：
  - 字面制表符（`\t`）编码为 `\\t`
  - 字面换行符（`\n`）编码为 `\\n`
  - 字面垂直制表符（`\v`）编码为 `\u000b`
  - 字面换页符（`\f`）编码为 `\\f`
  - 字面回车符（`\r`）编码为 `\\r`
  - 字面等号（`=`）编码为 `\u0061`
  - 字面反引号（`\`）编码为 `\u0060`
  - 字面双引号（`"`）编码为 `\u0022`
  - 字面与号（`&`）编码为 `\u0026`
  - 字面单引号（`'`）编码为 `\u0027`
  - 字面加号（`+`）编码为 `\u002b`
  - 字面正斜杠（`/`）编码为 `\/`
  - 字面小于号（`<`）编码为 `\u003c`
  - 字面大于号（`>`）编码为 `\u003e`
  - 字面左圆括号（`(`）编码为 `\u0028`
  - 字面右圆括号（`)`）编码为 `\u0029`
  - 字面左方括号（`[`）编码为 `\u005b`
  - 字面右方括号（`]`）编码为 `\u005d`
  - 字面左花括号（`{`）编码为 `\u007b`
  - 字面右花括号（`}`）编码为 `\u007d`
  - 字面反斜杠（`\`）编码为 `\\`

  此列表并不详尽。您可能需要根据上下文对更多字符进行编码。
- URL 内部：
  - 绝不允许用户输入出现在 URL 中。攻击者可能会注入 `javascript:...` 代码或恶意链接。
