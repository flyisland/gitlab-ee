## 描述

通过插入回车 / 换行（CRLF）字符，恶意用户可能会向 HTTP 响应中注入任意数据。通过修改 HTTP 响应，攻击者可以对系统的其他用户进行跨站脚本攻击或缓存投毒攻击。

<a id="remediation"></a>

## 修复

在构建 HTTP 头部响应时，绝不应该使用未经换行验证的用户输入。这包括用户提供的用于 HTTP 重定向的 URL。
