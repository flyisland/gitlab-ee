title: 缺失 Content-Type 头

<a id="description"></a>

## 描述

`Content-Type` 头确保用户代理正确解释接收到的数据。如果未发送此头，浏览器可能会误解数据，导致 MIME 混淆攻击。如果攻击者能够上传可通过浏览器访问的文件，他们可以上传可能被解释为 HTML 的文件，从而执行跨站脚本 (XSS) 攻击。

<a id="remediation"></a>

## 修复

确保所有资源返回与其格式匹配的正确 `Content-Type` 头。例如，当返回 JavaScript 文件时，响应头应为：`Content-Type: application/javascript`

为了增加保护，所有资源都应返回 `X-Content-Type-Options: nosniff` 头，以禁止用户代理解释资源。
