您可以为每个项目或群组创建新的安全策略，但在多个顶级群组之间重复相同的策略设置可能非常耗时，并会带来合规挑战。在创建策略之前，您应了解该策略应该是：

- 在特定项目或群组上强制执行。
- 在多个项目上强制执行。
- 在整个实例或顶级群组上强制执行

您可以通过多种方式强制执行策略：

- 要在单个项目或群组中的所有项目上强制执行策略，请在该项目或群组中创建策略。
- 要在多个项目上强制执行策略，请使用[安全策略项目](security_policy_projects.md)。安全策略项目是一种特殊类型的项目，您只能在其中添加策略，不能添加其他内容。要将安全策略项目中的策略强制执行到其他群组和项目，请从这些群组或项目链接到该安全策略项目。
- 要在整个极狐GitLab 私有化部署实例中同时强制执行策略和合规框架，实例管理员可以使用[合规与安全策略管理群组](compliance_and_security_policy_groups.md)。

<a id="policy-design-guidelines"></a>

## 策略设计指南

设计策略时：

- 最大化覆盖范围，同时最小化管理开销
- 确保职责分离

<a id="enforcement"></a>

### 强制执行

要强制执行策略以满足您的要求，请考虑以下因素：

- **继承**：默认情况下，策略会在其链接到的组织单元及其所有下级子群组和项目中强制执行。
- **范围**：要自定义策略强制执行，您可以定义策略的范围以匹配您的需求。

<a id="inheritance"></a>

#### 继承

要最大化策略覆盖范围，请将安全策略项目链接到能够实现您目标的最高组织单元：群组、子群组或项目。策略会在其链接到的组织单元及其所有下级子群组和项目中强制执行。在最高点强制执行可最大程度减少所需的安全策略数量，从而最小化管理开销。

您可以使用策略继承来逐步推出策略。例如，在推出新策略时，您可以先在单个项目上强制执行，然后进行测试。如果测试通过，您可以从该项目中移除该策略，并在群组上强制执行，逐级向上，直到该策略在所有适用的项目上强制执行。

在现有群组或子群组上强制执行的策略会自动在其下创建的任何新子群组和项目中强制执行，前提是：

- 新的子群组和项目包含在该策略的范围定义中（例如，范围包括此群组中的所有项目）。
- 现有群组或子群组已链接到该安全策略项目。

> [!note]
> JihuLab.com 用户可以在其顶级群组或跨子群组强制执行策略，但不能跨 JihuLab.com 顶级群组强制执行策略。极狐GitLab 私有化部署管理员可以在其实例中跨多个顶级群组强制执行策略。

以下示例说明了两个群组及其结构：

- Alpha 群组包含两个子群组，每个子群组包含多个项目。
- 安全与合规群组包含两个策略。

**Alpha** 群组（包含代码项目）

- **Finance**（子群组）
  - 项目 A
  - Accounts receiving（子群组）
    - 项目 B
    - 项目 C
- **Engineering**（子群组）
  - 项目 K
  - 项目 L
  - 项目 M

**安全与合规**群组（包含安全策略项目）

- Security Policy Management
- Security Policy Management - security policy project
  - SAST 策略
  - 密钥检测策略

假设未强制执行任何策略，请考虑以下示例：

- 如果 “SAST” 策略在 Alpha 群组上强制执行，则该策略适用于 Alpha 的两个子群组 Finance 和 Engineering，以及它们的所有项目和子群组。如果密钥检测策略也在 “Accounts receiving” 子群组上强制执行，则这两个策略都适用于项目 B 和 C。但是，只有 “SAST” 策略适用于项目 A。
- 如果 “SAST” 策略在 “Accounts receiving” 子群组上强制执行，则它仅适用于项目 B 和 C。没有策略适用于项目 A。
- 如果密钥检测策略在项目 K 上强制执行，则它仅适用于项目 K。没有其他子群组或项目适用任何策略。

<a id="scope"></a>

#### 范围

您可以通过以下方式细化策略的范围：

- 合规框架：在具有选定合规框架的项目上强制执行策略。
- 群组：
  - 群组中的所有项目，包括该群组的所有子群组及其项目。可选择排除特定项目。
  - 多个群组中的所有项目，包括这些群组的所有子群组及其项目。任何链接到同一安全策略项目的群组都可以列在策略中。可选择排除特定项目。
- 项目：包括或排除特定项目。只有链接到同一安全策略项目的项目才能列在策略中。

您可以在同一策略中一起应用这些细化设置。但是，排除优先于包括。

<a id="separation-of-duties"></a>

## 职责分离

职责分离对于成功实施策略至关重要。设计策略时，应在满足必要的合规和安全要求的同时支持开发工作流。

实施职责分离时：

- 集中定义策略，并与开发团队协作，确保策略支持他们的工作流。
- 将策略修改权限限制为仅授权角色。

要在群组、子群组或项目上强制执行安全策略项目，您必须具有以下任一条件：

- 该群组、子群组或项目中的所有者角色。
- 该群组、子群组或项目中具有 `manage_security_policy_link` 权限的[自定义角色](../../../custom_roles/_index.md)。

所有者角色和具有 `manage_security_policy_link` 权限的自定义角色遵循跨群组、子群组和项目的标准层级规则：

| 组织单元 | 群组所有者或群组 `manage_security_policy_link` 权限 | 子群组所有者或子群组 `manage_security_policy_link` 权限 | 项目所有者或项目 `manage_security_policy_link` 权限 |
|-------------------|---------------------------------------------------------------|---------------------------------------------------------------------|-------------------------------------------------------------------|
| 群组             | {{< yes >}} | {{< no >}}  | {{< no >}} |
| 子群组          | {{< yes >}} | {{< yes >}} | {{< no >}} |
| 项目           | {{< yes >}} | {{< yes >}} | {{< yes >}} |
