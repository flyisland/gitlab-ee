如果您的应用程序使用外部资源，通常需要使用密钥（例如令牌或密钥）对应用程序进行身份验证。如果密钥被推送到远程代码仓库，任何有权访问该代码仓库的人都可以冒充您或您的应用程序。

流水线密钥检测使用 CI/CD 作业检查您的极狐GitLab 项目中是否存在密钥。在本教程中，您将创建一个项目、配置流水线密钥检测，并学习如何分析其结果：

1. [创建项目](#create-a-project)
1. [检查作业输出](#check-the-job-output)
1. [启用合并请求流水线](#enable-merge-request-pipelines)
1. [添加虚假密钥](#add-a-fake-secret)
1. [排查密钥](#triage-the-secret)
1. [修复泄露](#remediate-a-leak)

<a id="before-you-begin"></a>

## 开始之前

在开始本教程之前，请确保您具备以下条件：

- 一个 JihuLab.com 账号。要充分利用流水线密钥检测的所有功能，如果您有旗舰版账号，应使用该账号。
- 对 CI/CD 有一定了解。

<a id="create-a-project"></a>

## 创建项目

首先，创建一个项目并启用密钥检测：

1. 在右上角，选择**创建新的** ({{< icon name="plus" >}}) 和**新建项目/仓库**。
1. 选择**创建空白项目**。
1. 输入项目详细信息：
   1. 输入名称和项目路径。
   1. 从**项目部署目标（可选）**下拉列表中，选择**未计划部署**。
   1. 选中**使用 README 初始化代码仓库**复选框。这样您之后就有地方向项目中添加内容。
   1. 选中**启用密钥检测**复选框。
1. 选择**创建项目**。

新项目已创建，并使用 README 和 `.gitlab-ci.yml` 文件进行初始化。CI/CD 配置包含 `Security/Secret-Detection.gitlab-ci.yml` 模板，该模板会在项目中启用流水线密钥检测。

<a id="check-the-job-output"></a>

## 检查作业输出

流水线密钥检测在名为 `secret_detection`的 CI/CD 作业中运行。扫描结果会写入 CI/CD 作业日志。每次扫描还会生成一份全面的报告作为作业产物。

要检查最近一次扫描的结果：

1. 在左侧边栏中，选择**构建** > **作业**。
1. 选择最近的 `secret_detection` 作业。如果您还没有运行新的流水线，应该只有一个作业。
1. 检查日志输出中是否有以下内容：
   - 有关扫描的信息，包括分析器版本和规则集。由于您自动启用了密钥检测，您的项目使用默认规则集。
   - 是否检测到任何密钥。您应该会看到 `no leaks found`。
1. 要下载完整报告，请在**作业产物**下选择**下载**。

<a id="enable-merge-request-pipelines"></a>

## 启用合并请求流水线

到目前为止，您已经使用流水线密钥检测扫描了默认分支中的提交。但是，要在将合并请求中的提交合并到默认分支之前分析它们，您需要启用合并请求流水线。

为此：

1. 将以下行添加到您的 `.gitlab-ci.yml` 文件中：

   ```yaml
   variables:
     AST_ENABLE_MR_PIPELINES: "true"
   ```

1. 保存更改并将其提交到项目的 `main` 分支。

<a id="add-a-fake-secret"></a>

## 添加虚假密钥

接下来，让我们通过在合并请求中“泄露”一个虚假密钥，使作业输出变得复杂一些：

1. 检出一个新分支：

   ```shell
   git checkout -b pipeline-sd-tutorial
   ```

1. 编辑项目的 README 并添加以下行。
   请务必删除 `-` 前后的空格，以匹配个人访问令牌的确切格式：

   ```markdown
   # To make the example work, remove
   # the spaces before and after the dash:
   glpat - 12345678901234567890
   ```

1. 提交并推送您的更改，然后打开一个合并请求将其合并到默认分支。

   合并请求流水线会自动运行。
1. 等待流水线完成，然后检查作业日志。您应该会看到 `WRN leaks found: 1`。
1. 下载作业产物并检查以确保其中包含以下信息：
   - 密钥类型。在此示例中，类型为 `"GitLab personal access token"`。
   - 有关该密钥用途的说明，以及您可以采取的一些修复泄露的步骤。
   - 泄露的严重性。由于个人访问令牌可用于在 JihuLab.com 上冒充用户，因此此泄露为 `Critical`。
   - 密钥的原始文本。
   - 有关密钥位置的一些信息：

     ```json
     "file": "README.md",
     "line_start": 97,
     "line_end": 97,
     ```

     在此示例中，密钥位于文件 `README.md`的第 97 行。

<a id="using-merge-request-reports"></a>

### 使用合并请求报告

{{< details >}}

- Tier: 旗舰版

{{< /details >}}

在非默认分支上检测到的密钥称为“发现项”。当发现项被合并到默认分支时，它就会变成“漏洞”。

合并请求的**报告**选项卡会显示安全扫描发现项，如果合并该合并请求，这些发现项可能会变成漏洞。

要查看发现项：

1. 选择您在上一步中创建的合并请求。
1. 选择**报告**选项卡。
1. 选择**安全扫描**。
1. 查看显示的信息。您应该会看到**密钥检测检测到 1 个新的潜在漏洞**。

要查看合并请求中所有发现项的详细视图，请选择**查看所有流水线发现项**。

<a id="triage-the-secret"></a>

## 排查密钥

{{< details >}}

- Tier: 旗舰版

{{< /details >}}

在极狐GitLab 旗舰版上，作业输出还会写入：

- 流水线的**安全**选项卡。
- 如果发现项变成漏洞，则写入漏洞报告。

为了演示如何使用 UI 排查密钥，让我们创建一个漏洞并在漏洞报告中更改其状态：

1. 合并您在上一步中创建的合并请求，然后等待流水线完成。

   虚假密钥被添加到 `main`，这会导致发现项变成漏洞。
1. 在左侧边栏中，选择**安全** > **漏洞报告**。
1. 选择该漏洞的**描述**以查看：
   - 有关密钥类型的详细信息。
   - 修复指导。
   - 有关检测到该漏洞的时间和位置的信息。
1. 在右侧边栏的**状态**部分中，选择**编辑**。
   1. 从**状态**下拉列表中，选择**驳回为... 用于测试**。
   1. 添加一条评论，说明您为什么将虚假密钥添加到项目中。
   1. 选择**更改状态**。

该漏洞不再出现在漏洞报告的首页上。

<a id="remediate-a-leak"></a>

## 修复泄露

如果您将密钥添加到远程代码仓库，该密钥就不再安全，必须尽快撤销。即使密钥尚未合并到默认分支，您也应该撤销并替换它们。

您修复泄露所采取的确切步骤取决于您组织的安全策略，但至少您应该：

1. 撤销密钥。密钥被撤销后即失效，无法再用于冒充合法活动。
1. 从代码仓库中移除该密钥。

具体的修复指导会写入 `secret-detection` 作业日志，并可在漏洞报告详情页上查看。
