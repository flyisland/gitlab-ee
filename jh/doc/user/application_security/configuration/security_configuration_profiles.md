安全配置配置文件是集中式设置，用于定义安全扫描器在您项目中的运行方式与时机。
使用安全配置配置文件可以高效管理整个组织的安全扫描器。基于配置文件的方式能够以最少的手动配置应用最佳实践。

当您将配置文件应用于群组时，它会被应用到该群组中的每个独立项目。配置文件不会附加到群组本身，并且配置文件或子群组之间不存在继承关系。

使用[默认配置文件](#default-profiles)可在数分钟内以最少配置启用预配置的安全扫描。

<a id="configure-security-scanners"></a>

## 配置安全扫描器

要评估和管理您的配置文件，请将群组的[安全清单](../security_inventory/_index.md#view-the-security-inventory)作为您的中央仪表板。

<a id="review-test-coverage"></a>

### 审查测试覆盖率

要查看群组中扫描器（例如 SAST、DAST 和密钥检测）的高级状态（**已启用**、**未启用**或**失败**）：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到您的群组。
1. 在左侧边栏中，选择 **安全** > **安全清单**。
1. 在安全清单中，审查**测试覆盖率**列。

<a id="change-individual-project-coverage"></a>

### 更改单个项目的覆盖率

要配置特定项目：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到您的群组。
1. 在左侧边栏中，选择 **安全** > **安全清单**。
1. 在项目旁边，选择垂直省略号 ({{< icon name="ellipsis_v" >}}) 并选择 **管理工具覆盖范围**。
1. 打开或关闭各个扫描器。

<a id="apply-a-profile-to-multiple-projects"></a>

### 将配置文件应用于多个项目

为节省时间，您可以一次性将安全设置应用于多个项目：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到您的群组。
1. 在左侧边栏中，选择 **安全** > **安全清单**。
1. 选择要应用设置的多个项目或整个子群组。
1. 选择**批量操作**下拉菜单并选择**管理安全扫描器**。
1. 选择**将默认配置文件应用到全部**以在所选范围内标准化您的安全态势。

<a id="default-profiles"></a>

## 默认配置文件

极狐GitLab 提供了预配置扫描器设置的默认配置文件，让您可以以最少配置启用安全扫描。

<a id="secret-detection-profile"></a>

### 密钥检测配置文件

当您应用密钥检测配置文件时，您会在整个开发工作流中启用针对密钥的推荐基线保护。该配置文件会激活以下扫描触发条件：

- **推送保护**：扫描所有 Git 推送事件，并在检测到密钥时阻止推送，防止密钥进入您的代码库。
- **合并请求流水线**：每当新提交被推送到有开放合并请求的分支时，自动运行一次扫描。结果范围限定于该合并请求引入的新漏洞。适用于所有分支。
- **分支流水线（仅默认分支）**：当变更合并或推送到默认分支时自动运行，为您提供默认分支密钥检测态势的完整视图。适用于所有分支。

<a id="sast-profile"></a>

### SAST 配置文件

当您应用 SAST 配置文件时，您将使用推荐配置在项目中启用静态应用安全测试。该配置文件会激活以下扫描触发条件：

- **合并请求流水线**：每当新提交被推送到有开放合并请求的分支时，自动运行一次 SAST 扫描。结果仅包含该合并请求引入的新漏洞。适用于所有分支。
- **分支流水线（仅默认分支）**：当变更合并或推送到默认分支时自动运行，为您提供默认分支 SAST 态势的完整视图。适用于默认分支。

<a id="view-details-about-a-profile"></a>

### 查看配置文件的详细信息

要查看密钥检测配置文件的技术详情：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到您的群组。
1. 在左侧边栏中，选择 **安全** > **安全清单**。
1. 选择**密钥检测**配置文件。
1. 查看以下信息：
   - **分析器类型**：配置文件的类型（例如**密钥检测**、**SAST**）。
   - **扫描触发条件**：配置文件支持的触发条件（例如**推送保护**、**合并请求流水线**、**分支流水线**）。
   - **状态**：使用覆盖率状态指示器显示配置文件在当前上下文中是处于**活动**还是**已禁用**状态。

<a id="coverage-status-indicators"></a>

## 覆盖率状态指示器

系统在清单中使用视觉提示来指示您的项目是否受到保护：

- **实心绿色条**：扫描器已完全启用并处于活动状态。
- **灰色/空白条**：扫描器尚未配置或启用。
- **部分条**：部分保护处于活动状态（例如，配置文件中可用的某些触发条件已启用，但其他触发条件未启用）。
- **工具提示**：悬停在任何覆盖率条上，可以查看基于流水线的扫描的**上次扫描**日期以及特定的流水线状态。

与基于流水线的扫描不同，推送保护没有上次扫描日期，因为它是在推送过程中实时运行的。

<a id="troubleshooting"></a>

## 故障排除

在使用安全配置配置文件时，您可能会遇到以下问题。

<a id="no-last-scan-date-appears-for-push-protection"></a>

### 推送保护没有显示上次扫描日期

推送保护是基于事件的，而非基于计划的。它在 `git push` 过程中实时截取密钥。由于它在 `push` 命令执行时即处于活动状态，因此不像基于流水线的扫描器那样有上次扫描日期。

<a id="scanner-status-is-active-in-the-dashboard-but-not-enabled-in-inventory-tooltip"></a>

### 扫描器在仪表板中显示活动状态，但在清单工具提示中显示未启用

当项目使用旧版设置的同时也分配了新配置文件时，可能会出现这种情况。

要解决此问题：

1. 查看**安全配置**页面，获取最准确的当前配置文件状态。
1. 如有必要，从您的 `.gitlab-ci.yml` 文件中移除旧版扫描器配置，以完全依赖基于配置文件的配置。

> [!note]
> 清单工具提示正在优化中，以反映旧版和基于配置文件的设置的组合状态。

<a id="understanding-legacy-versus-profile-based-configuration"></a>

### 了解旧版配置与基于配置文件的配置

如果您要从旧版扫描器配置迁移到基于配置文件的配置，请注意以下区别：

- 旧版配置：需要手动编辑 YAML 文件或单个项目设置才能启用扫描器。
- 基于配置文件的配置：使用集中式系统，您可以一次将默认配置文件应用于多个项目，而无需修改代码。

建议使用基于配置文件的配置，以便更轻松地管理并在各项目间实现更高的一致性。
