<a id="description"></a>

## 描述

许多文件操作旨在在受限目录中进行。通过使用特殊元素，如 `..` 和 `/` 分隔符，攻击者可以逃逸出受限位置，访问系统上其他位置的文件或目录。最常见的特殊元素之一是 `../` 序列，在大多数现代操作系统中，它被解释为当前位置的父目录。这被称为相对路径遍历。路径遍历还包括使用绝对路径名，如 `/usr/local/bin`，这可能也有助于访问意外文件。这被称为绝对路径遍历。

在许多编程语言中，注入空字节（`0` 或 `NULL`）可能允许攻击者截断生成的文件名，以扩大攻击范围。例如，软件可能会在任何路径名后添加 `.txt`，从而将攻击者限制为文本文件，但空字节注入可能有效地移除此限制。

此检查修改请求中的参数（路径、查询字符串、头部、JSON、XML 等），以尝试访问受限文件及 Web 根目录之外的文件。然后分析日志和响应，以尝试检测文件是否被成功访问。

<a id="remediation"></a>

## 修复

路径遍历攻击技术允许攻击者访问可能位于 Web 文档根目录之外的文件、目录和命令。攻击者可能操纵 URL，使网站执行或泄露 Web 服务器上任意文件的内容。任何暴露基于 HTTP 接口的设备都可能容易受到路径遍历攻击。

大多数网站将用户访问限制在文件系统的特定部分，通常称为“Web 文档根目录”或“CGI 根目录”。这些目录包含供用户访问的文件以及驱动 Web 应用程序功能所需的可执行文件。要访问文件系统上的任何文件或执行命令，路径遍历攻击将利用特殊字符序列的能力。

最基本的路径遍历攻击使用 `../` 特殊字符序列来更改 URL 中请求的资源位置。尽管大多数流行的 Web 服务器会阻止此技术逃逸出 Web 文档根目录，但 `../` 序列的替代编码可能有助于绕过安全过滤器。这些方法变体包括正斜杠字符的有效和无效 Unicode 编码（`..%u2216` 或 `..%c0%af`）、基于 Windows 的服务器上的反斜杠字符（`..`）、URL 编码字符（`%2e%2e%2f`）以及反斜杠字符的双重 URL 编码（`..%255c`）。

即使 Web 服务器正确限制了 URL 路径中的路径遍历尝试，Web 应用程序本身仍可能因对用户提供的输入处理不当而存在漏洞。这是使用模板机制或从文件加载静态文本的 Web 应用程序的常见问题。在攻击的变体中，原始 URL 参数值被替换为 Web 应用程序动态脚本之一的文件名。因此，结果可能泄露源代码，因为文件被解释为文本而非可执行脚本。这些技术通常使用额外的特殊字符，如点号（`.`）以揭示当前工作目录的列表，或 `%00` NULL 字符以绕过基本的文件扩展名检查。
