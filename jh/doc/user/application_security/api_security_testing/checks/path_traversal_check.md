<a id="description"></a>

## 描述

许多文件操作都应在受限目录内进行。通过使用 `..` 和 `/` 分隔符等特殊元素，攻击者可以逃逸到受限位置之外，访问系统上其他位置的文件或目录。最常见的特殊元素之一是 `../` 序列，在大多数现代操作系统中，它被解释为当前位置的父目录。这称为相对路径遍历。路径遍历还包括使用绝对路径名，例如 `/usr/local/bin`，这也可能有助于访问意料之外的文件。这称为绝对路径遍历。

在许多编程语言中，注入空字节（`0` 或 `NULL`）可能使攻击者截断生成的文件名，从而扩大攻击范围。例如，软件可能会为任何路径名添加 `.txt`，从而将攻击者限制在文本文件范围内，但注入空字节可能会有效移除这一限制。

此检查会修改请求中的参数（路径、查询字符串、请求头、JSON、XML 等），尝试访问受限文件以及 Web 根目录之外的文件。随后分析日志和响应，尝试检测文件是否被成功访问。

<a id="remediation"></a>

## 修复

路径遍历攻击技术使攻击者能够访问可能位于 Web 文档根目录之外的文件、目录和命令。攻击者可以操纵 URL，使网站执行或泄露 Web 服务器上任意位置的文件内容。任何暴露基于 HTTP 接口的设备都可能受到路径遍历攻击。

大多数网站将用户访问限制在文件系统的特定部分，通常称为“Web 文档根目录”或“CGI 根目录”。这些目录包含供用户访问的文件以及驱动 Web 应用程序功能所需的可执行文件。为了访问文件系统上任意位置的文件或执行命令，路径遍历攻击会利用特殊字符序列的能力。

最基本的路径遍历攻击使用 `../` 特殊字符序列来更改 URL 中请求的资源位置。尽管大多数主流 Web 服务器会阻止此技术逃逸 Web 文档根目录，但 `../` 序列的其他编码方式可能有助于绕过安全过滤器。这些方法变体包括正斜杠字符的有效和无效 Unicode 编码（`..%u2216` 或 `..%c0%af`）、基于 Windows 的服务器上的反斜杠字符（`..`）、URL 编码字符（`%2e%2e%2f`）以及反斜杠字符的双重 URL 编码（`..%255c`）。

即使 Web 服务器正确限制了 URL 路径中的路径遍历尝试，Web 应用程序本身仍可能因对用户提供输入的处理不当而存在漏洞。这是使用模板机制或从文件加载静态文本的 Web 应用程序的常见问题。在攻击的变体中，原始 URL 参数值会被替换为 Web 应用程序某个动态脚本的文件名。因此，由于文件被解释为文本而非可执行脚本，结果可能泄露源代码。这些技术通常还会使用其他特殊字符，例如点号（`.`）来泄露当前工作目录的列表，或使用 `%00` 空字符来绕过基本的文件扩展名检查。
