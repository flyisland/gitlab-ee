工作计划是附加在工作项上的结构化 Markdown 文档。它捕获一项工作的意图、方法和步骤。

工作计划为极狐GitLab Duo Agent 提供商定的规范，以及工作项上可供人工审阅的产物。有了此上下文，Agent 可依据的信息比简短提示更多，因此可以更准确地执行工作。

您可以使用极狐GitLab Duo 创建工作计划，也可以手动编写。极狐GitLab Duo 根据工作项上下文起草工作计划，然后由您进行完善。随后，Agent 将工作计划作为工作的主要规范。

工作计划是 [极狐GitLab Duo Agent Platform](../duo_agent_platform/_index.md) 和规范驱动开发工作流的一部分。

您可以将工作计划添加到议题和任务中。

为工作项启用规划后，**工作计划** 小组件将出现并显示工作计划状态：

- **尚未创建**：工作项没有工作计划，您可以创建一个。
- **无工作计划**：工作项没有工作计划，且您没有权限创建。
- **可查看**：工作项已有工作计划。

<a id="benefits"></a>

## 优势

工作计划将意图与实现分开：

- 工作项描述捕获意图，即您想要什么以及为什么。
  人们阅读描述以了解目标。
- 工作计划捕获实现，即如何执行工作。
  Agent 遵循工作计划来执行工作。

这种分离为您带来三个优势：

- 意图保护：Agent 在与工作项描述分开的字段中迭代工作计划，因此即使计划在多次运行中发生变化，您的意图也能保持完整。
- 计划审阅：Agent 在生成工作计划后会暂停，以便您在任何工作开始前审阅、完善和批准计划。
- Agent 聚焦：由于工作计划是专用字段，被要求规划工作的 Agent 会将上下文放在那里，而不是重写描述或工作项的其他部分。

<a id="when-to-use-a-workplan"></a>

## 何时使用工作计划

当您计划将工作交给 Agent 时，请使用工作计划，无论是通过选择 **实现** 还是自行将计划提供给编码 Agent。当 Agent 执行工作时，工作计划能发挥最大价值。

对于小型或已充分理解的变更，您不需要工作计划，因为规划带来的额外工作可能超过其节省的精力。

<a id="turn-on-planning-for-a-work-item"></a>

## 为工作项启用规划

默认情况下，**工作计划** 小组件和置信度评分在工作项上是隐藏的。要显示它们，请为该工作项启用规划。

先决条件：

- 工作项必须是议题或任务。
- 具有编辑工作项的权限。

要启用规划：

- 在工作项上，在右上角，选择 **规划**。

**工作计划** 小组件将出现在工作项上，**规划** 按钮不再出现。为工作项启用规划后，您无法将其关闭。

<a id="create-a-workplan"></a>

## 创建工作计划

创建工作计划以描述如何完成一项工作。

先决条件：

- 已为工作项启用规划。
- 具有编辑工作项的权限。

您可以使用极狐GitLab Duo 生成工作计划，也可以手动编写。

<a id="generate-a-workplan-with-gitlab-duo"></a>

### 使用极狐GitLab Duo 生成工作计划

先决条件：

- 已启用 [极狐GitLab Duo Chat](../gitlab_duo_chat/agentic_chat.md)。

要使用极狐GitLab Duo 生成工作计划：

1. 在工作项上，在 **工作计划** 小组件中，选择 **生成**。
1. 在极狐GitLab Duo Chat 中，回答 [计划者 Agent](../duo_agent_platform/agents/foundational_agents/planner.md) 的问题，直到 Agent 获得足够的上下文。
1. 审阅提议的计划并批准。

批准计划后，极狐GitLab Duo 会将其写入 **工作计划** 小组件。

<a id="create-a-workplan-manually"></a>

### 手动创建工作计划

要手动创建工作计划：

1. 在工作项上，在 **工作计划** 小组件中，选择 **更多选项** > **手动创建**。
1. 可选。从模板下拉列表中，选择工作计划模板。
1. 输入工作计划内容。要在编辑器之间切换，请选择 **切换到富文本编辑** 或 **切换到纯文本编辑**。
1. 选择 **保存更改**。

工作计划模板是文件名以 `.plan` 结尾的[描述模板](../project/description_templates.md)。

<a id="view-a-workplan"></a>

## 查看工作计划

要查看工作计划：

- 在工作项上，在 **工作计划** 小组件中，选择 **查看**。

工作计划将在面板中打开并显示渲染后的内容。

<a id="edit-a-workplan"></a>

## 编辑工作计划

先决条件：

- 具有编辑工作项的权限。

要编辑工作计划：

1. 在工作项上，在 **工作计划** 小组件中，选择 **查看**。
1. 在面板中，选择 **编辑**。
1. 进行您的更改。
1. 选择 **保存更改**。

要放弃更改，请选择 **取消**。

<a id="regenerate-a-workplan"></a>

## 重新生成工作计划

重新生成工作计划以使用极狐GitLab Duo 的新版本替换其内容。

先决条件：

- 具有编辑工作项的权限。

要重新生成工作计划：

1. 在工作项上，在 **工作计划** 小组件中，选择 **查看**。
1. 在面板中，选择 **更多操作** ({{< icon name="ellipsis_v" >}}) > **重新生成工作计划**。
1. 在极狐GitLab Duo Chat 中，回答计划者 Agent 的问题，直到 Agent 获得足够的上下文。

极狐GitLab Duo 会用新版本替换现有的工作计划。

<a id="delete-a-workplan"></a>

## 删除工作计划

先决条件：

- 具有编辑工作项的权限。

要删除工作计划：

1. 在工作项上，在 **工作计划** 小组件中，选择 **查看**。
1. 在面板中，选择 **更多操作** ({{< icon name="ellipsis_v" >}}) > **删除工作计划**。
1. 在确认对话框中，选择 **删除**。

此操作无法撤销。

<a id="confidence-score"></a>

## 置信度评分

> [!flag]
> 此功能的可用性由功能标志控制。
> 此功能可用于测试，但尚未准备好用于生产环境。

置信度评分显示工作项准备好供 Agent 执行的程度。极狐GitLab Duo 根据工作项的完整性、清晰度和范围界定进行评分，然后将评分映射到置信度级别。

先决条件：

- 已为工作项启用规划。

在工作项的 **工作计划** 小组件中，置信度级别显示为 **低**、**中** 或 **高**。无论工作项是否有工作计划，都会显示该评分。

要提高评分，请在工作项描述和工作计划步骤中添加更多详细信息，例如需求、验收标准和约束条件。

<a id="implement-a-workplan-with-gitlab-duo"></a>

## 使用极狐GitLab Duo 实现工作计划

当工作计划存在时，极狐GitLab Duo 可以在合并请求中实现它。极狐GitLab Duo 将工作计划视为主要规范，仅将工作项描述和评论用作附加上下文。

先决条件：

- 已启用极狐GitLab Duo Agent Platform 远程任务流。

要使用极狐GitLab Duo 实现工作计划，请使用以下方法之一：

- 在工作项上，在 **工作计划** 小组件中，选择 **实现**。
- 打开工作计划，然后从面板中实现它：
  1. 在工作项上，在 **工作计划** 小组件中，选择 **查看**。
  1. 在面板中，选择 **实现**。
