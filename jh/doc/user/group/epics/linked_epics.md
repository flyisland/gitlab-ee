关联的史诗是任意两个史诗之间的双向关系，显示在史诗描述下方的区块中。您可以关联不同群组中的史诗。

只有当用户能够看到两个史诗时，该关系才会显示在 UI 中。当您尝试关闭存在未解决阻塞项的史诗时，会显示一条警告。

要管理关联的史诗，请参阅[关联的史诗 API](../../../api/linked_epics.md)。

<a id="ways-to-use-linked-epics"></a>

## 关联的史诗的用途

您可以使用关联的史诗来解决多种规划与协调难题。以下示例展示了关联的史诗如何帮助团队更高效地协作。

<a id="cross-functional-initiatives"></a>

### 跨职能计划

使用关联的史诗来协调多个团队之间的工作，并跟踪相互依赖的交付成果。当多个团队共同开展一项大型计划时，每个团队都可以管理自己的史诗，同时保持对相关工作的可见性。

<!-- vale gitlab_base.OxfordComma = NO -->
例如，在发布新功能时，开发团队和营销团队通常会并行工作。
开发团队在其史诗中跟踪技术实现，而营销团队则在另一个史诗中规划
推广活动。
<!-- vale gitlab_base.OxfordComma = YES -->

通过关联这些史诗：

- 团队可以跟踪技术工作与推广工作之间的依赖关系。
- 每个团队在保持自主性的同时，与更广泛的计划保持一致。
- 相关方可以了解发布的完整范围。
- 团队可以识别并解决跨组织边界的阻塞项。

这种协调有助于打破孤岛，并确保计划的各个方面保持同步。

当您跨群组关联史诗时：

- 每个团队将自己的工作保留在自己的群组中。
- 团队无需在群组之间切换即可查看相关工作。
- 状态更新会在关联的史诗之间自动流转。

<a id="dependency-management"></a>

### 依赖关系管理

使用关联的史诗来管理和跟踪工作依赖关系。当基础设施变更完成之前开发工作无法开始时，关联的史诗可以帮助团队管理这些依赖关系。

例如，在构建新功能时，团队通常需要先完成基础设施更新，开发工作才能开始。基础设施团队在一个史诗中跟踪其数据库迁移工作，而开发团队则在另一个史诗中规划功能实现。

通过关联这些史诗：

- 团队可以跟踪基础设施工作何时可供开发使用。
- 开发团队可以更好地规划其冲刺容量。
- 产品经理可以识别潜在的工作流延迟。
- 团队无需频繁开会即可了解进展。

这种可见性有助于团队按正确顺序完成工作，并避免任务受阻。

当您关联史诗以显示依赖关系时：

- 基础设施工作与开发工作保持关联。
- 团队知道何时可以开始自己的工作。
- 状态更新会在史诗之间自动流转。

<a id="higher-level-planning"></a>

### 更高层级的规划

使用关联的史诗将短期执行与长期规划连接起来。在管理一系列发布时，您可以组织高层级目标并跟踪各个功能交付成果。

例如，在规划跨越多个季度的多次发布时，您可以为每次发布创建单独的史诗。然后将这些发布史诗关联到一个跟踪整体项目的中心路线图史诗。

通过关联这些史诗：

- 团队可以了解自己的工作如何融入更大的战略。
- 产品经理可以跟踪多次发布的进展。
- 团队在专注于当前工作的同时，也能看到未来计划。
- 相关方可以同时监控细粒度进展和高层级进展。

这种结构有助于团队在推进当前工作的同时，保持更广泛的目标。

当您关联史诗以进行规划时：

- 每次发布的进展都会显示在路线图中。
- 团队可以提前看到即将开展的工作。
- 状态更新会汇总到更高层级的视图中。

<a id="add-a-linked-item"></a>

## 添加关联项

将一个史诗与另一个项关联：

- 史诗
- 议题
- 任务
- 目标
- 关键结果

先决条件：

- 您必须在两个群组中，或在群组和项目中，拥有访客、计划者、报告者、开发者、维护者或所有者角色。
- 对于 JihuLab.com：您正在编辑的史诗必须位于极狐GitLab 旗舰版的群组中。
  您要关联的史诗可以位于较低版本的群组中。

要将一个史诗关联到另一个项：

1. 在史诗的**关联项**部分，选择**添加**。
1. 选择两个项之间的关系。可以是：

   - **与之相关**
   - **阻塞**
   - **被阻塞**

1. 要输入关联项，可以：

   - 输入 `#`，后跟该项的编号。例如，`#123`。
   - 输入 `#`，后跟该项标题中的一个词。例如，`#Deliver`。
   - 粘贴该项的完整 URL。

   同一群组中的项只需指定引用编号即可。
   来自不同群组的项需要额外信息，例如
   群组名称。例如：

   - 同一群组：`#44`
   - 不同群组：`group#44`

   有效的引用会添加到一个临时列表中，供您查看。

1. 选择**添加**。

随后，关联项会按关系分组显示在史诗上。只有当用户能够看到两个项时，该关系才会显示在 UI 中。

或者，您也可以使用[快速操作](../../project/quick_actions.md)添加关联项：

- `/relate`
- `/blocks`
- `/blocked_by`

<a id="remove-a-linked-item"></a>

## 移除关联项

先决条件：

- 您必须拥有史诗所在群组的访客、计划者、报告者、开发者、维护者或所有者角色。

要移除关联项：

1. 在描述底部，找到工作项的**关联项**部分。
1. 对于每个关联项，选择**移除**（{{< icon name="close" >}}）。

该关系会从两个史诗中移除。

<a id="blocking-epics"></a>

## 阻塞史诗

当您[添加关联项](#add-a-linked-item)时，可以表明它**阻塞**或
**被阻塞**另一个史诗。

如果您尝试使用**关闭史诗**按钮关闭被阻塞的史诗，会出现一条确认消息。
