链接史诗是任意两个史诗之间的双向关系，并显示在史诗描述下方的块中。您可以在不同群组中链接史诗。

仅当用户可以查看两个史诗时，该关系才在 UI 中显示。
当您尝试关闭一个存在未解决阻碍项的史诗时，会显示警告。

要管理链接，请参阅[链接史诗 API](../../../api/linked_epics.md)。

<a id="ways-to-use-linked-epics"></a>

## 使用链接史诗的方式

您可以使用链接史诗来解决多个规划和协调挑战。以下示例展示了链接史诗如何帮助团队更有效地合作。

<a id="cross-functional-initiatives"></a>

### 跨职能计划

使用链接史诗来协调多个团队之间的工作并跟踪相互依赖的可交付成果。当团队合作进行大型项目时，每个团队可以管理自己的史诗，同时保持对相关工作的可见性。

例如，在发布新功能时，开发团队和市场团队通常会并行工作。开发团队在其史诗中跟踪技术实现，而市场团队在单独的史诗中计划推广活动。

通过链接这些史诗：

- 团队可以跟踪技术和推广工作之间的依赖关系。
- 每个团队保持自主，同时保持在整个计划上的协调一致。
- 利益相关者可以了解整个发布的范围。
- 团队可以跨组织边界识别和解决阻碍项。

这种协调有助于打破孤岛，确保计划的所有方面保持同步。

当跨群组链接史诗时：

- 每个团队将工作保留在自己的群组中。
- 团队无需切换群组即可看到相关工作。
- 状态更新在链接的史诗之间自动流动。

<a id="dependency-management"></a>

### 依赖管理

使用链接史诗来管理和跟踪工作依赖关系。当基础设施变更完成后开发才能开始时，链接史诗可帮助团队管理这些依赖关系。

例如，构建新功能时，团队通常需要先完成基础设施更新。基础设施团队在一个史诗中跟踪数据库迁移工作，而开发团队在另一个史诗中计划功能实现。

通过链接这些史诗：

- 团队可以跟踪基础设施工作何时准备好供开发使用。
- 开发团队可以更好地规划其迭代容量。
- 产品经理可以识别潜在的流程延迟。
- 团队无需频繁开会即可了解进展。

这种可见性有助于团队按正确顺序完成工作，避免任务阻塞。

当链接史诗以显示依赖关系时：

- 基础设施和开发工作保持连接。
- 团队知道何时可以开始自己的工作。
- 状态更新在史诗之间自动流动。

<a id="higher-level-planning"></a>

### 高层规划

使用链接史诗将短期执行与长期规划联系起来。管理一系列发布时，您可以组织高级目标并跟踪各个功能交付。

例如，计划多个季度内的多个发布时，您可以为每个发布创建单独的史诗。然后将这些发布史诗链接到跟踪整体项目的中央路线图史诗。

通过链接这些史诗：

- 团队可以了解自己的工作如何适应更大的策略。
- 产品经理可以跨多个发布跟踪进度。
- 团队专注于当前工作，同时查看未来计划。
- 利益相关者可以同时监控详细和高层进度。

这种结构有助于团队在当前工作取得进展的同时保持更广泛的目标。

当链接史诗进行规划时：

- 每个发布的进展在路线图中可见。
- 团队可以提前看到即将开展的工作。
- 状态更新汇总到高层视图。

## 添加关联项

{{< history >}}

- 在极狐GitLab 18.1 中引入了链接议题、任务、目标和关键结果的能力。

{{< /history >}}

链接史诗和另一个：

- 史诗
- 议题
- 任务
- 目标
- 关键结果

先决条件：

- 您必须在两个群组中拥有访客、计划者、报告者、开发者、维护者或所有者角色，或者在群组和项目中拥有该角色。
- 对于 JihuLab.com：您正在编辑的史诗必须位于使用极狐GitLab 旗舰版的群组中。您链接的史诗可以位于较低版本的群组中。

要将一个史诗链接到另一个项：

1. 在史诗的 **关联项** 部分，选择 **添加**。
1. 选择两项之间的关系。可以是：

   - **与之相关**
   - **阻塞**
   - **被阻塞**

1. 要输入关联项，可以：

   - 输入 `#`，后跟项的编号。例如，`#123`。
   - 输入 `#`，后跟项标题中的一个词。例如，`#Deliver`。
   - 粘贴项的完整 URL。

   相同群组的项可以仅通过引用编号指定。
   来自不同群组的项需要额外的信息，比如群组名称。例如：

   - 相同群组：`#44`
   - 不同群组：`group#44`

   有效的引用将被添加到一个临时列表中，供您审阅。

1. 选择 **添加**。

关联项随后会按关系分组显示在史诗上。
仅当用户可以看到两项时，关系才显示在 UI 中。

或者，您可以使用[快速操作](../../project/quick_actions.md)添加关联项：

- `/relate`
- `/blocks`
- `/blocked_by`

<a id="remove-a-linked-item"></a>

## 移除关联项

先决条件：

- 您必须在史诗的群组中拥有访客、计划者、报告者、开发者、维护者或所有者角色。

要移除关联项：

1. 在描述底部，找到工作项的 **关联项** 部分。
1. 对于每个关联项，选择 **移除** ({{< icon name="close" >}})。

关系将从两个史诗中移除。

<a id="blocking-epics"></a>

## 阻塞史诗

当您[添加关联项](#add-a-linked-item)时，可以表明它 **阻塞** 或 **被阻塞于** 另一个史诗。

如果您尝试使用 **关闭史诗** 按钮关闭一个被阻塞的史诗，会出现一条确认消息。
