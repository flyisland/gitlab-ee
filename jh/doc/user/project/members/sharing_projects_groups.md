您可以通过邀请共享：

- 将项目共享给群组。
- 将群组共享给另一个群组。

<a id="sharing-projects"></a>

## 共享项目

当您希望某个群组可以访问您的项目时，您可以将该[群组](../../group/_index.md)邀请到项目中。该群组的直接成员和继承成员将获得对该项目的访问权限，该项目随即成为**共享项目**。

在这种情况下，继承成员是指从父群组继承到被邀请群组中的成员。只有被邀请群组的成员才能访问共享项目。如果您希望被邀请群组的子群组成员也能访问该项目，则必须邀请该子群组。

下表概述了可以访问共享项目的群组成员。

| 群组成员来源                                                  | 对共享项目的访问权限 |
|----------------------------------------------------------------------|--------------------------|
| 被邀请群组的直接成员                           | {{< yes >}}              |
| 被邀请群组的继承成员                        | {{< yes >}}              |
| 被邀请群组的共享成员 <sup>1</sup>              | {{< yes >}}              |
| 子群组的直接成员，但不是被邀请群组的成员    | {{< no >}}               |
| 子群组的继承成员，但不是被邀请群组的成员 | {{< no >}}               |

**脚注**：

1. 极狐GitLab 支持将项目访问权限扩展到共享群组成员，但不推荐这种做法。[史诗 122](https://gitlab.com/groups/gitlab-org/-/epics/122) 提议更改此行为，并过渡到以团队模型来共享群组。

您所邀请群组的[可见性级别](../../public_access.md)不能比项目更严格。例如，您可以邀请：

- 将**私有**群组邀请到**私有**项目。
- 将**私有**群组邀请到**内部**项目。
- 将**私有**群组邀请到**公开**项目。
- 将**内部**群组邀请到**内部**项目。
- 将**内部**群组邀请到**公开**项目。
- 将**公开**群组邀请到**公开**项目。

如果项目的顶级群组不允许在层级之外共享该项目，则被邀请的群组或子群组必须位于项目的[命名空间](../../namespace/_index.md)中。

<a id="member-access-and-roles"></a>

### 成员访问权限和角色

当您将群组邀请到项目中时，以下成员将获得对该项目的访问权限：

- 群组的直接成员。
- 群组的继承成员。
- 与被邀请群组[共享](#invite-a-group-to-a-group)的其他群组的成员。

每个成员的访问权限取决于：

- 他们在群组中的角色。
- 您在邀请该群组时选择的最大角色。

被邀请成员保留这两个角色中较低的一个。例如，如果某成员在其群组中拥有访客角色，而您将其群组添加到项目中并设置最大角色为维护者，那么他们在该项目中仍保留访客角色。

此外：

- 在群组页面上，该项目列在 **共享项目** 标签页中。
- 在项目的 **成员** 页面上，该群组列在 **群组** 标签页中。此列表同时包含公开群组和私有群组。
- 在项目的 **成员** 页面上，被邀请群组的成员列在 **成员** 标签页中。
- 在用量配额页面上，个人资料旁带有 **项目邀请** 徽章的成员会计入共享项目顶级群组的计费成员数。

被邀请群组的名称和成员来源在 **成员** 和 **群组** 标签页上会被[遮蔽](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/144638)，除非满足以下任一条件：

- 被邀请群组是公开的。
- 当前用户是被邀请群组的成员。
- 当前用户是项目的所有者。

> [!note]
> 对于无权访问被邀请群组的成员，被邀请群组的名称和成员来源会被遮蔽。
> 项目所有者可以查看被邀请群组的成员详情，以帮助他们管理项目的访问权限。

<a id="examples"></a>

### 示例

命名空间 `group/subgroup01/project`中的项目：

- 可以共享给 `group/subgroup02` 或 `group/subgroup01/subgroup03`。
- 可以共享给 `group_abc`，除非项目的顶级群组不允许在层级之外共享该项目。

对于由 `Group 1` 创建的项目：

- `Group 1`的成员可以访问该项目。
- `Group 1`的所有者可以将 `Group 2` 邀请到该项目。
  这样，`Group 1` 和 `Group 2`的成员都可以访问该共享项目。

<a id="invite-a-group-to-a-project"></a>

### 将群组邀请到项目

先决条件：

- 您必须拥有该项目的所有者角色。
- 不得阻止将该项目与其他群组共享。
- 您必须是被邀请群组或子群组的成员。

要将群组邀请到项目：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的项目。
1. 在左侧边栏中，选择**管理** > **成员**。
1. 选择**邀请群组**。
1. 在 **选择要邀请的群组** 列表中，选择您要邀请的群组。
1. 在 **选择最大角色** 列表中，选择被邀请群组成员在项目中可以拥有的[角色](../../permissions.md)。被邀请成员获得以下两者中较低的一个：
   - 您选择的最大角色
   - 他们在群组中已有的角色

   被邀请群组成员在项目中的角色不能高于他们在群组中的角色。有关更多信息，请参阅[成员访问权限和角色](#member-access-and-roles)。
1. 可选。选择一个 **访问过期日期**。
   从该日期起，被邀请群组将无法再访问该项目。
1. 选择**邀请**。

被邀请的群组会显示在 **群组** 标签页中。您也可以使用 REST API [列出项目邀请的群组](../../../api/projects.md#list-all-invited-groups-in-a-project)。

私有群组会：

- 对未授权用户遮蔽。
- 显示在受保护分支、受保护标签和受保护环境的项目设置中。

**成员** 标签页显示：

- 直接添加到项目的成员。
- 项目所添加到的群组[命名空间](../../namespace/_index.md)的继承成员。

被邀请群组的成员不会显示在 **成员** 标签页中，除非启用了 `webui_members_inherited_users` 功能标志。

<a id="examples-1"></a>

#### 示例

名为 `project-01`的项目具有以下直接成员：

- 用户 A，所有者
- 用户 B，维护者

名为 `group-01`的群组具有以下直接成员：

- 用户 C，所有者
- 用户 D，维护者
- 用户 E，报告者

当 `group-01` 以 `Developer` 权限被邀请到 `project-01` 时，用户具有以下角色：

- 用户 A，所有者
- 用户 B，维护者
- 用户 C，开发者
- 用户 D，开发者
- 用户 E，报告者

当 `group-01` 以 `Owner` 权限被邀请到 `project-01` 时，用户具有以下角色：

- 用户 A，所有者
- 用户 B，维护者
- 用户 C，所有者
- 用户 D，维护者
- 用户 E，报告者

<a id="view-shared-projects"></a>

### 查看共享项目

共享项目是指通过 [**邀请群组**](#invite-a-group-to-a-project) 操作邀请您的群组成员访问其资源的项目。

要查看与您的群组共享访问权限的项目：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在群组页面上，选择 **共享项目** 标签页。

此时会显示共享项目列表。您也可以使用 REST API [列出群组的共享项目](../../../api/groups.md#list-shared-projects)。

<a id="prevent-a-project-from-being-shared-with-groups"></a>

### 阻止项目与群组共享

将项目与另一个群组共享会增加可以邀请更多成员加入该项目的用户数量。每个（子）群组都可能成为额外的访问权限来源，这可能会造成混乱且难以控制。

要阻止项目与其他群组共享：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在左侧边栏中，选择**设置** > **通用**。
1. 展开 **权限和群组功能** 部分。
1. 选择 **`<group_name>` 中的项目不能与其他群组共享**。
1. 选择**保存更改**。

启用此设置后：

- 它会应用于所有子群组，除非被群组所有者覆盖。
- 已添加到项目的群组将失去对该项目的访问权限。

禁用此设置后：

- 它仅应用于此群组，而不应用于其子群组。
- 要为所有子群组禁用此设置，您必须逐个更新每个子群组。

## 共享群组

当您希望另一个群组的成员可以访问您的群组时，您可以将该[群组](../../group/_index.md)邀请到您的群组中。该群组的直接成员将获得对该群组的访问权限，该群组随即成为**共享群组**。

只有被邀请群组的直接成员才能访问共享群组，继承成员、共享成员或子群组成员都不能访问。要授予子群组成员访问权限，请直接邀请该子群组。

下表概述了可以访问共享群组的群组成员：

| 群组成员来源                                        | 对共享群组的访问权限 |
|------------------------------------------------------------|------------------------|
| 被邀请群组的直接成员                 | {{< yes >}}            |
| 被邀请群组的继承成员              | {{< no >}}             |
| 被邀请群组的共享成员                 | {{< no >}}             |
| 子群组的成员，但不是被邀请群组的成员 | {{< no >}}             |

<a id="member-access-and-roles-1"></a>

### 成员访问权限和角色

每个成员的访问权限取决于：

- 他们在被邀请群组中的角色。
- 您在邀请该群组时选择的最大角色。

被邀请成员保留这两个角色中较低的一个。例如，如果某成员在其群组中拥有访客角色，而您将其群组邀请到另一个群组并设置最大角色为维护者，那么他们在新群组中仍保留访客角色。

在您将群组邀请到您的群组后：

- 在群组概览页面上，与该群组共享过的群组列在 **共享群组** 标签页中。
- 在群组的 **成员** 页面上，被邀请群组列在 **群组** 标签页中。此列表同时包含公开群组和私有群组。
- 在群组的 **成员** 页面上，被邀请群组的成员列在 **成员** 标签页中。
- 在群组的用量配额页面上，个人资料旁带有 **群组邀请** 徽章的被邀请群组直接成员会计入邀请方群组的计费成员数。

被邀请群组的名称和成员来源在 **成员** 和 **群组** 标签页上会被[遮蔽](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/144638)，除非满足以下任一条件：

- 被邀请群组是公开的。
- 当前用户是被邀请群组的成员。
- 当前用户是项目的所有者。

> [!note]
> 对于无权访问被邀请群组的成员，被邀请群组的名称和成员来源会被遮蔽。
> 但是，即使群组所有者无法访问私有被邀请群组，他们也可以看到私有被邀请群组成员的来源。
> 此行为旨在帮助群组所有者更好地管理他们拥有的群组的成员关系。

<a id="examples-2"></a>

### 示例

`User A` 是 `Group 1`的直接成员，并拥有该群组的维护者角色。`Group 2` 以开发者角色邀请 `Group 1`。`User A` 在 `Group 2`中拥有开发者角色。

`User B` 是 `Group 1`的继承成员。当 `Group 1` 被邀请时，该用户不会获得对 `Group 2`的访问权限。

### 将群组邀请到群组

与将群组邀请到项目类似，您可以将一个群组邀请到另一个群组。

先决条件：

- 您必须拥有要邀请其他群组加入的群组的所有者角色。
- 您必须能够访问要邀请的群组。

要将群组邀请到您的群组：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在左侧边栏中，选择**管理** > **成员**。
1. 选择**邀请群组**。
1. 在 **选择要邀请的群组** 列表中，选择您要邀请的群组。
1. 在 **选择最大角色** 列表中，选择被邀请群组成员在群组中可以拥有的[角色](../../permissions.md)。被邀请成员获得以下两者中较低的一个：
   - 您选择的最大角色
   - 他们在被邀请群组中已有的角色

   被邀请成员的角色不能高于他们在被邀请群组中的角色。有关更多信息，请参阅[成员访问权限和角色](#member-access-and-roles-1)。
1. 为群组中的用户选择最高的[角色](../../permissions.md)或[自定义角色](../../custom_roles/_index.md#assign-a-custom-role-to-an-invited-group)。
1. 可选。选择一个 **访问过期日期**。
   从该日期起，被邀请群组将无法再访问该群组。
1. 选择**邀请**。

<a id="remove-an-invited-group"></a>

### 移除被邀请的群组

要移除被邀请的群组：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在左侧边栏中，选择**管理** > **成员**。
1. 选择 **群组** 标签页。
1. 在您要移除的群组右侧，选择 **移除群组**（{{< icon name="remove" >}}）。

当您从您的群组中移除被邀请群组时：

- 被邀请群组的所有直接成员将不再有权访问您的群组。
- 被邀请群组的成员将不再计入您群组的计费成员数。

### 查看共享群组

共享群组是指通过 [**邀请群组**](#invite-a-group-to-a-group) 操作邀请您的群组成员访问其资源的群组。

要查看与您的群组共享访问权限的群组：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在群组页面上，选择 **共享群组** 标签页。

此时会显示共享群组列表。您也可以使用 REST API [列出群组的共享群组](../../../api/groups.md#list-shared-groups)。

<a id="prevent-inviting-groups-outside-the-group-hierarchy"></a>

### 阻止邀请群组层级之外的群组

您可以配置顶级群组，使其子群组和项目无法邀请顶级群组层级之外的其他群组。此选项仅适用于顶级群组。

例如，在以下群组和项目层级中：

- **Animals** > **Dogs** > **Dog Project**
- **Animals** > **Cats**
- **Plants** > **Trees**

如果您为 **Animals** 群组阻止邀请层级之外的群组：

- **Dogs** 可以邀请群组 **Cats**。
- **Dogs** 不能邀请群组 **Trees**。
- **Dog Project** 可以邀请群组 **Cats**。
- **Dog Project** 不能邀请群组 **Trees**。

要阻止邀请群组层级之外的群组：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组。
1. 在左侧边栏中，选择**设置** > **通用**。
1. 展开 **权限和群组功能**。
1. 选择 **成员无法邀请 `<group_name>` 及其子群组之外的群组**。
1. 选择**保存更改**。

<a id="setting-up-a-group-for-collaboration"></a>

## 为协作设置群组

如果您打算与外部用户就您群组中的项目进行协作，请考虑以下最佳实践：

- 根据组织需求合理地组织您的群组和子群组。避免创建不必要的群组。
- 如果您需要管理大量用户，请考虑将用户组织在独立于项目组织群组的用户群组中。将这些用户群组共享到它们需要访问的群组和项目中。
- 仔细考虑您邀请哪些群组加入您的项目。只邀请需要访问权限的群组，以防止过度共享并维护安全性。
- 当您邀请群组时：
  - 合理设置最大角色。最好分配所需的最低权限，而不是默认使用最高角色。
  - 被邀请群组的子群组成员不会获得对该项目的访问权限。您可能更愿意单独邀请子群组。
- 检查属于多个可访问某项目的群组的用户的最大角色。为防止出现意外的高权限，您可能需要更改这些用户的角色。
- 定期审查群组对共享项目的访问权限，并酌情更新。如果某个群组不再需要访问某个项目，请将其移除。
