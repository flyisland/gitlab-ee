你可以通过邀请共享：

- 一个项目与一个群组。
- 一个群组与另一个群组。

<a id="sharing-projects"></a>

## 共享项目

当你希望一个群组能够访问你的项目时，
你可以邀请该 [群组](../../group/_index.md) 到项目中。
该群组的直接和继承成员将获得项目的访问权限，该项目即成为一个 **共享项目**。

在这种情况下，继承成员是指从父群组继承到被邀请群组的成员。
只有被邀请群组的成员才能访问共享项目。
如果你希望被邀请群组的子群组成员也能访问该项目，你必须邀请该子群组。

下表概述了哪些群组成员可以访问共享项目。

| 群组成员来源                                                    | 访问共享项目的权限 |
|----------------------------------------------------------------|-------------------|
| 被邀请群组的直接成员                                            | {{< yes >}}       |
| 被邀请群组的继承成员                                            | {{< yes >}}       |
| 被邀请群组的共享成员 <sup>1</sup>                               | {{< yes >}}       |
| 子群组的直接成员，但不是被邀请群组的成员                        | {{< no >}}        |
| 子群组的继承成员，但不是被邀请群组的成员                        | {{< no >}}        |

**脚注**:

1. 极狐GitLab 支持将项目访问权限扩展至共享群组成员，但不推荐此方法。[史诗 122](https://gitlab.com/groups/gitlab-org/-/epics/122) 提议更改此行为，并过渡到用于共享群组的团队模型。

你邀请的群组的 [隐私级别](../../public_access.md) 不能比项目更严格。
例如，你可以邀请：

- 一个 **私有** 群组到一个 **私有** 项目。
- 一个 **私有** 群组到一个 **内部** 项目。
- 一个 **私有** 群组到一个 **公共** 项目。
- 一个 **内部** 群组到一个 **内部** 项目。
- 一个 **内部** 群组到一个 **公共** 项目。
- 一个 **公共** 群组到一个 **公共** 项目。

如果项目的顶级群组不允许在层级之外共享项目，
则受邀的群组或子群组必须位于项目的 [命名空间](../../namespace/_index.md) 内。

<a id="member-access-and-roles"></a>

### 成员访问和角色

当你邀请一个群组到一个项目时，以下成员将获得项目的访问权限：

- 直接群组成员。
- 继承群组成员。
- 与被邀请群组有 [共享关系](sharing_projects_groups.md#invite-a-group-to-a-group) 的其他群组的成员。

每个成员的访问权限取决于：

- 他们在群组中的角色。
- 你邀请群组时选择的最大角色。

受邀成员将保留这两个角色中较低的一个。例如，如果一个成员在其群组中拥有 访客
角色，而你将其群组添加到一个最大角色为 维护者 的项目中，
他们将在项目中保留 访客 角色。

此外：

- 在群组的页面上，该项目会列在 **共享项目** 选项卡上。
- 在项目的 **成员** 页面上，该群组会列在 **群组** 选项卡上。此列表包含公共和私有群组。
- 在项目的 **成员** 页面上，受邀群组的成员会列在 **成员** 选项卡上。
- 在用量配额页面上，个人资料旁带有 **项目邀请** 标记的成员将计入共享项目顶级群组的付费成员中。

[在极狐GitLab 16.11 及更高版本中](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/144638)，
受邀群组的名称和成员来源在 **成员** 和 **群组** 选项卡上会被遮盖，
除非满足以下任一条件：

- 受邀群组是公共的。
- 当前用户是受邀群组的成员。
- 当前用户是项目的 所有者。

> [!note]
> 无法访问受邀群组的成员无法看到受邀群组的名称和成员来源。
> 项目 所有者 可以查看受邀群组的成员详情，以帮助管理其项目的访问权限。

<a id="examples"></a>

### 示例

命名空间 `group/subgroup01/project` 中的一个项目：

- 可以与 `group/subgroup02` 或 `group/subgroup01/subgroup03` 共享。
- 可以与 `group_abc` 共享，除非项目的顶级群组不允许在层级之外共享项目。

对于由 `Group 1` 创建的项目：

- `Group 1` 的成员可以访问该项目。
- `Group 1` 的 所有者 可以邀请 `Group 2` 到该项目。
  这样，`Group 1` 和 `Group 2` 的成员都可以访问该共享项目。

<a id="invite-a-group-to-a-project"></a>

### 邀请群组到项目

{{< history >}}

- 在极狐GitLab 16.10 中，[更改](https://gitlab.com/gitlab-org/gitlab/-/issues/219230) 为在 **成员** 页面的 **成员** 选项卡中显示受邀群组成员，[使用一个功能标志](../../../administration/feature_flags/_index.md) 名为 `webui_members_inherited_users`。默认禁用。
- 功能标志 `webui_members_inherited_users` 在极狐GitLab 17.0 中 [在 JihuLab.com 和私有化部署上启用](https://gitlab.com/gitlab-org/gitlab/-/issues/219230)。
- 子群组和项目的直接成员的访问过期日期在极狐GitLab 17.4 中 [移除](https://gitlab.com/gitlab-org/gitlab/-/issues/471051)，且功能标志 `webui_members_inherited_users` 在极狐GitLab 17.4 中 [移除](https://gitlab.com/gitlab-org/gitlab/-/issues/364078)。

{{< /history >}}

前提条件：

- 你必须拥有项目的 所有者 角色。
- 必须允许与其他群组共享项目。
- 你必须是受邀群组或子群组的成员。

要将群组邀请到项目中：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的项目。
1. 在左侧边栏中，选择 **管理** > **成员**。
1. 选择 **邀请群组**。
1. 在 **选择要邀请的群组** 列表中，选择你要邀请的群组。
1. 从 **选择最大角色** 列表中，选择受邀群组成员在项目中可以拥有的 [角色](../../permissions.md)。受邀成员将保留以下中的较低者：
   - 你选择的最大角色
   - 他们在群组中的现有角色

   受邀群组成员在项目中的角色不能高于他们在群组中的角色。更多信息，请参阅 [成员访问和角色](#member-access-and-roles)。
1. 可选。选择一个 **访问过期日期**。
   从此日期起，受邀群组将不再能访问该项目。
1. 选择 **邀请**。

受邀群组显示在 **群组** 选项卡上。
你还可以使用 REST API [列出项目的所有受邀群组](../../../api/projects.md#list-all-invited-groups-in-a-project)。

私有群组：

- 对未授权用户进行遮盖。
- 在受保护分支、受保护标签和受保护环境的项目设置中显示。

**成员** 选项卡显示：

- 直接添加到项目的成员。
- 项目所属群组 [命名空间](../../namespace/_index.md) 的继承成员。

除非启用了 `webui_members_inherited_users` 功能标志，否则受邀群组的成员不会显示在 **成员** 选项卡上。

<a id="examples-1"></a>

#### 示例

一个名为 `project-01` 的项目有以下直接成员：

- 用户 A， 所有者
- 用户 B， 维护者

一个名为 `group-01` 的群组有以下直接成员：

- 用户 C， 所有者
- 用户 D， 维护者
- 用户 E， 报告者

当 `group-01` 被邀请到 `project-01` 并赋予 开发者 权限时，用户拥有以下角色：

- 用户 A， 所有者
- 用户 B， 维护者
- 用户 C， 开发者
- 用户 D， 开发者
- 用户 E， 报告者

当 `group-01` 被邀请到 `project-01` 并赋予 所有者 权限时，用户拥有以下角色：

- 用户 A， 所有者
- 用户 B， 维护者
- 用户 C， 所有者
- 用户 D， 维护者
- 用户 E， 报告者

### 查看共享项目

共享项目是指通过 [**邀请群组**](#invite-a-group-to-a-project) 操作，邀请你的群组成员访问其资源的项目。

要查看与你的群组共享访问权限的项目：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的群组。
1. 在群组页面上，选择 **共享项目** 选项卡。

<a id="prevent-a-project-from-being-shared-with-groups"></a>

### 防止项目与其他群组共享

将项目与另一个群组共享会增加能够邀请更多成员加入该项目的用户数。
每个（子）群组都可能成为额外的访问权限来源，
这可能会令人困惑且难以控制。

要防止项目与其他群组共享：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的群组。
1. 在左侧边栏中，选择 **设置** > **通用**。
1. 展开 **权限和群组功能** 部分。
1. 选择 **`<group_name>` 中的项目不能与其他群组共享**。
1. 选择 **保存更改**。

启用此设置后：

- 它适用于所有子群组，除非被群组 所有者 覆盖。
- 已经添加到项目的群组将失去对其的访问权限。

禁用此设置后：

- 它仅适用于此群组，不适用于其子群组。
- 若要为所有子群组禁用此设置，你必须分别更新每个子群组。

## 共享群组

当你希望另一个群组的成员能够访问你的群组时，
你可以邀请该 [群组](../../group/_index.md) 到你的群组中。
该群组的直接成员将获得群组的访问权限，该群组即成为一个 **共享群组**。

只有受邀群组的直接成员才能访问共享群组，而不是继承、共享或子群组成员。要授予子群组成员访问权限，请直接邀请子群组。

下表概述了哪些群组成员可以访问共享群组：

| 群组成员来源                                        | 访问共享群组的权限 |
|----------------------------------------------------|-------------------|
| 被邀请群组的直接成员                                | {{< yes >}}       |
| 被邀请群组的继承成员                                | {{< no >}}        |
| 被邀请群组的共享成员                                | {{< no >}}        |
| 子群组的成员，但不是被邀请群组的成员                | {{< no >}}        |

<a id="member-access-and-roles-1"></a>

### 成员访问和角色

每个成员的访问权限取决于：

- 他们在受邀群组中的角色。
- 你邀请群组时选择的最大角色。

受邀成员将保留这两个角色中较低的一个。例如，如果一个成员在其群组中拥有 访客
角色，而你将其群组邀请到另一个群组并赋予最大角色为 维护者，
他们将在新群组中保留 访客 角色。

将群组邀请到你的群组后：

- 在群组的概览页面上，与该群组共享的其他群组会列在 **共享群组** 选项卡上。
- 在群组的 **成员** 页面上，受邀群组会列在 **群组** 选项卡上。此列表包含公共和私有群组。
- 在群组的 **成员** 页面上，受邀群组的成员会列在 **成员** 选项卡上。
- 在群组的用量配额页面上，受邀群组的直接成员，若其个人资料旁带有 **群组邀请** 标记，将计入邀请群组的付费成员中。

[在极狐GitLab 16.11 及更高版本中](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/144638)，
受邀群组的名称和成员来源在 **成员** 和 **群组** 选项卡上会被遮盖，
除非满足以下任一条件：

- 受邀群组是公共的。
- 当前用户是受邀群组的成员。
- 当前用户是项目的 所有者。

> [!note]
> 无法访问受邀群组的成员无法看到受邀群组的名称和成员来源。
> 但是，即使群组 所有者 无法访问私有受邀群组，他们也可以看到私有受邀群组成员来源。
> 此行为旨在帮助群组 所有者 更好地管理他们拥有的群组的成员资格。

<a id="examples-2"></a>

### 示例

`用户 A` 是 `Group 1` 的直接成员，并拥有该群组的 维护者 角色。
`Group 2` 邀请 `Group 1` 并赋予 开发者 角色。
`用户 A` 在 `Group 2` 中拥有 开发者 角色。

`用户 B` 是 `Group 1` 的继承成员。当 `Group 1` 被邀请时，此用户无法访问 `Group 2`。

### 将群组邀请到群组

- 你必须能够访问你要邀请的群组。

要将群组邀请到你的群组：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的群组。

   - 你选择的最大角色
   - 他们在受邀群组中的现有角色

   受邀成员的角色不能高于他们在受邀群组中的角色。更多信息，请参阅 [成员访问和角色](#member-access-and-roles-1)。
1. 为群组中的用户选择最高的 [角色](../../permissions.md) 或 [自定义角色](../../custom_roles/_index.md#assign-a-custom-role-to-an-invited-group)。

   从此日期起，受邀群组将不再能访问该群组。
1. 选择 **邀请**。

<a id="remove-an-invited-group"></a>

### 移除受邀群组

要移除受邀群组：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的群组。
1. 在左侧边栏中，选择 **管理** > **成员**。
1. 选择 **群组** 选项卡。
1. 在你要移除的群组右侧，选择 **移除群组** ({{< icon name="remove" >}})。

当你从你的群组中移除受邀群组后：

- 所有受邀群组的直接成员将不再能访问你的群组。
- 受邀群组的成员将不再计入你的群组的付费成员中。

<a id="prevent-inviting-groups-outside-the-group-hierarchy"></a>

### 防止邀请群组层级之外的群组

你可以配置顶级群组，使其子群组和项目
无法邀请顶级群组层级之外的其他群组。
此选项仅适用于顶级群组。

例如，在以下群组和项目层级中：

- **Animals** > **Dogs** > **Dog Project**
- **Animals** > **Cats**
- **Plants** > **Trees**

如果你为 **Animals** 群组阻止了在层级之外邀请群组：

- **Dogs** 可以邀请群组 **Cats**。
- **Dogs** 不能邀请群组 **Trees**。
- **Dog Project** 可以邀请群组 **Cats**。
- **Dog Project** 不能邀请群组 **Trees**。

要防止邀请群组层级之外的群组：

1. 在顶部栏中，选择 **搜索或跳转到** 并找到你的群组。
1. 在左侧边栏中，选择 **设置** > **通用**。
1. 展开 **权限和群组功能**。
1. 选择 **成员无法邀请 `<group_name>` 及其子群组之外的群组**。
1. 选择 **保存更改**。

<a id="setting-up-a-group-for-collaboration"></a>

## 为协作设置群组

如果你打算与外部用户协作处理群组中的项目，请考虑以下最佳实践：

- 根据组织需求逻辑性地构建你的群组和子群组。避免创建不必要的群组。
- 如果你需要管理大量用户，考虑将用户组织在与项目组织群组分开的群组中。将这些用户群组共享到他们需要访问的群组和项目中。
- 仔细考虑邀请哪些群组到你的项目中。仅邀请需要访问的群组，以防止过度共享并维护安全。
- 当你邀请一个群组时：
  - 适当设置最大角色。最好分配所需的最低权限，而不是默认为最高角色。
  - 受邀群组的子群组成员不会获得项目的访问权限。你可能更喜欢分别邀请子群组。
- 检查属于多个有权访问项目的群组的用户的最大角色。为防止意外的高权限，你可能需要更改用户的角色。
- 定期审查群组对共享项目的访问权限，并根据需要进行更新。如果某个群组不再需要访问某个项目，请将其移除。
