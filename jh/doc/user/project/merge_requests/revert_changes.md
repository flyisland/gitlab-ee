代码中的错误在所难免。版本控制通过撤回操作，让修复这些错误变得可能。

当你撤回一个提交时，你会创建一个新的提交（撤回提交），该提交会逆转错误更改，而不会从项目历史中抹除问题所在。撤回提交提供清晰的审计跟踪，而不是留下之前提交的空白。撤回提交遵循项目的访问控制和流程，并且：

- 移除原始提交中添加的行。
- 恢复原始提交中删除的行。
- 将原始提交中修改的行恢复到之前的状态。

撤回不仅限于提交。如果错误更改跨越多个提交，考虑从合并请求撤回所有更改，而不是逐个提交撤回。这种方法能提供更清晰的审计跟踪。

<a id="revert-a-merge-request"></a>

## 撤回合并请求

合并请求合并后，你可以撤回合并请求中的所有更改。

前提条件：

- 你必须拥有项目的角色，允许你编辑合并请求，并向代码仓添加代码。
- 你的项目必须使用[合并方法](methods/_index.md#fast-forward-merge)**合并提交**，在项目的**设置** > **合并请求**中设置。

  在极狐GitLab 16.9 及更高版本中，如果满足以下任一条件，你可以从极狐GitLab UI 撤回快进式提交：

  - 提交被压缩，或
  - 合并请求包含单个提交。

要撤回合并请求 `Example`：

1. 在顶部栏，选择 **搜索或跳转到** 并找到你的项目。
2. 在左侧边栏，选择 **代码** > **合并请求**。
3. 在二级菜单，选择 **已合并**，然后选择你的合并请求（此处为 `Example`）。
4. 滚动到合并请求报告区域，找到显示 **合并者** 信息的报告。
5. 选择 **撤回**。
6. 在 **撤回至分支**，选择要将更改撤回到的分支。
7. 要立即撤回，而不通过合并请求：
   1. 取消勾选 **发起新合并请求**。
   2. 选择 **撤回**，`Example` 的撤回即完成。
8. 要在新的合并请求中审查撤回而不是立即撤回，选择 **发起新合并请求**，然后：
   1. 填写撤回合并请求的字段，然后选择 **创建合并请求**。
   2. 当合并请求合并后，`Example` 的撤回即完成。

<a id="revert-a-commit"></a>

## 撤回提交

你可以将代码仓中的任何提交撤回到以下任一位置：

- 当前分支。
- 一个新的合并请求。

前提条件：

- 你在项目中的角色必须允许你编辑合并请求，并向代码仓添加代码。
- 该提交必须尚未被撤回，因为在此情况下，**撤回**选项不会显示。

操作步骤：

1. 在顶部栏，选择 **搜索或跳转到** 并找到你的项目。
2. 如果你知道包含该提交的合并请求：
   1. 在左侧边栏，选择 **代码** > **合并请求**，然后选择你的合并请求。
   2. 选择 **提交**，然后选择你想要撤回的提交标题。这会在合并请求的上下文中显示提交。
   3. 在二级菜单下方，极狐GitLab 显示消息 **查看提交 `00001111`**，其中 `00001111` 是提交的哈希值。选择提交哈希以显示提交页面。
3. 如果你不知道提交源自哪个合并请求：
   1. 在左侧边栏，选择 **代码** > **提交**。
   2. 选择提交标题以显示有关提交的完整信息。
4. 在右上角，选择 **选项**，然后选择 **撤回**。
5. 在 **撤回至分支**，选择要将更改撤回到的分支。
6. 要立即撤回，而不通过合并请求：
   1. 取消勾选 **发起新合并请求**。
   2. 选择 **撤回**。
7. 要在新的合并请求中审查撤回而不是立即撤回，选择 **发起新合并请求**，然后：
   1. 填写撤回合并请求的字段，然后选择 **创建合并请求**。
   2. 当合并请求合并后，提交撤回即完成。

<a id="revert-a-merge-commit-to-a-different-parent-commit"></a>

### 撤回合并提交到不同的父提交

当你撤回一个合并提交时，合并到的分支（通常是 `main`）始终是第一个父提交。要将合并提交撤回到不同的父提交，你必须从命令行撤回该提交，请参见[使用 Git 撤回和撤销更改](../../../topics/git/undo.md#revert-a-merge-commit-to-a-different-parent)。
