代码仓库保护可防止对代码库的未授权更改，同时保持开发工作流顺畅。这些控制措施可帮助您解决常见的开发难题，包括：

- 意外提交到生产分支或受保护分支。
- 提交历史中暴露敏感数据。
- 绕过代码评审流程。
- 对关键文件的未授权更改。
- 未经验证的提交作者身份。
- 不符合规范的代码进入主分支。

通过组合不同的保护方法，您可以创建相互配合的验证点，以执行组织的标准。

订阅极狐GitLab 更高层级的用户可使用更多工具，以应用全面的安全扫描、执行合规要求，并跨多个项目和群组管理漏洞。在这些环境中，部分保护方法可能已由您的组织强制执行。有关这些高级安全工具的详细信息，请参阅[保护您的应用程序](../../application_security/secure_your_application.md)。

<a id="protection-methods"></a>

## 保护方法

极狐GitLab 提供多种保护方法，它们协同工作以保护您的代码仓库。每种方法满足不同的安全需求，可组合使用以实现全面保护。

| 保护方法 | 描述 | 使用场景 | 实例 | 群组 | 项目 |
|-------------------|-------------|-------------|----------|--------|----------|
| [受保护分支](branches/protected.md)                      | 控制分支权限，以确保代码的稳定性和质量。                         | 控制谁可以推送和合并、防止意外删除、强制执行评审，或规范强制推送权限。 | {{< no >}}  | {{< yes >}} | {{< yes >}} |
| [合并请求审批](../merge_requests/approvals/_index.md) | 在更改合并前需要审批的评审流程。                                   | 要求代码评审、创建审批规则，或配置审批设置。                                      | {{< no >}}  | {{< yes >}} | {{< yes >}} |
| [推送规则](push_rules.md)                                      | 在提交、文件和标签进入代码仓库前对其进行验证的预接收 Git 钩子。 | 评估提交内容、执行分支名称规则、防止删除标签，或要求签名提交。              | {{< yes >}} | {{< yes >}} | {{< yes >}} |
| [代码所有者](../codeowners/_index.md)                           | 定义谁对代码库中特定文件和目录具备专业知识。                 | 要求专家审批特定文件的更改，或确定负责代码维护的一方。       | {{< no >}}  | {{< no >}}  | {{< yes >}} |
| [状态检查](../merge_requests/status_checks.md)              | 调用外部系统以验证合并请求状态的 API 调用。                              | 与第三方工作流工具集成，或根据外部质量要求进行验证。                      | {{< no >}}  | {{< no >}}  | {{< yes >}} |

<a id="branch-rules"></a>

## 分支规则

为帮助您管理多种保护方法，极狐GitLab 提供了统一的[分支规则](branches/branch_rules.md)界面，用于管理受保护分支、审批规则和状态检查。使用项目设置中的**分支规则**页面，即可在一个位置配置所有分支保护、查看各分支的保护状态，并管理复杂的保护组合。

> [!note]
> 如需进行群组保护，请在群组设置中配置受保护分支和推送规则。
> **分支规则**页面仅在项目中可用。群组规则适用于该群组中的所有项目，
> 并与您创建的任何项目专属规则协同工作。

<a id="configure-your-protection-strategy"></a>

## 配置您的保护策略

根据您的工作流和安全需求选择保护方法。以下是一些示例策略。

<a id="baseline-protection"></a>

### 基线保护

要在所有代码仓库中建立一致的安全标准：

- 为群组配置默认分支保护，以自动保护新项目。
- 设置受保护分支，以控制谁可以推送和合并。
- 要求合并请求审批，以强制执行同行评审。

<a id="comprehensive-protection"></a>

### 全面保护

通过分层保护来保护关键项目：

- 设置受保护分支和审批规则，以控制谁可以推送和合并。
- 对包含敏感逻辑的文件要求代码所有者审批。
- 强制执行签名提交，以验证作者身份。
- 添加状态检查，以根据自动化测试进行验证。
- 对群组应用推送规则，以在所有项目中执行标准。

<a id="targeted-protection"></a>

### 针对性保护

要满足特定的安全需求：

- 当文件需要领域专家评审时，要求代码所有者审批。
- 强制执行推送规则，以维护提交标准和内容限制。
- 当需要外部验证时，添加状态检查。
- 为特定工作流需求配置审批规则。

<a id="get-started"></a>

## 开始使用

先决条件：

- 您必须拥有项目的维护者或所有者角色，或群组的所有者角色。
- 确定哪些分支需要保护。
- 确定您的合规和安全需求。

要配置和实施代码仓库保护：

1. 选择您的范围：
   - 对于群组规则，转到群组的**设置** > **代码仓库**。
   - 对于项目专属规则，转到项目的**设置** > **代码仓库** >
     **分支规则**。

1. 设置基线保护：
   - 为默认分支和其他关键分支创建受保护分支。
     - 在群组设置中：**设置** > **代码仓库** > **受保护分支**。
     - 在项目设置中：**设置** > **代码仓库** > **分支规则**。
   - 在**设置** > **合并请求** > **合并请求审批**中配置合并权限和审批要求。

1. 添加评审要求：
   - 在 `CODEOWNERS` 文件中为特定文件定义代码所有者。
   - 在**设置** > **合并请求**中设置审批规则。

1. 启用安全控制：
   - 配置推送规则：
     - 对于群组：**设置** > **代码仓库** > **推送规则**。
     - 对于项目：**设置** > **代码仓库** > **推送规则**。
   - 在**设置** > **代码仓库** > **推送规则** >
     **拒绝未签名的提交**中启用签名提交。

1. 测试您的配置：
   - 创建一个测试合并请求。
   - 验证保护规则是否正确触发。
   - 根据结果调整设置。
