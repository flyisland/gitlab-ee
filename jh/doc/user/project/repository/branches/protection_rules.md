保护规则控制对分支的访问，并决定当多条规则应用于同一分支时会发生什么。它们可帮助您为代码仓库分支实施适当的安全措施。这些规则涵盖：

- 权限级别、优先级和规则冲突。
- 跨多条匹配规则的强制推送权限。
- 代码所有者审批。
- 群组与项目之间的保护设置。

<a id="rule-behaviors"></a>

## 规则行为

当某个分支匹配多条保护规则时，将应用以下行为：

- 群组规则应用于群组中的所有项目，且无法从项目设置中修改。
  更多信息，请参见[跨群组和项目的规则](#rules-across-groups-and-projects)。
- 当某个分支匹配多条规则时，以最宽松的规则为准。但是，
  [代码所有者审批](#code-owner-approval)使用最严格的规则。
- 像 `main` 这样的精确分支名称不会覆盖像 `m*` 这样的通配符模式。

<a id="push-and-merge-permissions"></a>

## 推送和合并权限

当分支受保护时，默认行为会强制执行以下限制：

| 操作                   | 谁可以执行 |
|:-------------------------|:--------------|
| 保护分支         | 具有维护者或所有者角色的用户。 |
| 推送到分支       | 任何具有 **已允许** 权限的人。(1) |
| 强制推送到分支 | 任何人都不可以。       |
| 删除分支        | 任何人都不可以。(2)   |

1. 具有开发者角色的用户可以在群组中创建项目，但可能不允许
   最初推送到[默认分支](default.md)。
1. 任何人都无法使用 Git 命令删除受保护分支。但是，至少具有维护者
   角色的用户可以从 UI 或 API [删除受保护分支](protected.md#delete-protected-branches)。

当您配置这些权限时，选择某个角色会向具有该角色及所有更高角色的用户授予访问权限。例如：

- 选择 **维护者** 会向具有维护者和所有者角色的用户授予访问权限。
- 选择 **开发者 + 维护者** 会向具有开发者、维护者和所有者角色的用户授予访问权限。

此行为可确保具有更高权限的用户保留较低权限用户可用的访问权限。

<a id="force-push-permissions"></a>

## 强制推送权限

强制推送权限遵循相同的“以最宽松规则为准”逻辑。例如，考虑以下规则，其中包含[通配符](protected.md#use-wildcard-rules)：

| 分支名称模式 | 允许强制推送 |
|---------------------|------------------|
| `v1.x`              | 是              |
| `v1.*`              | 否               |
| `v*`                | 否               |

名为 `v1.x`的分支匹配全部三个分支名称模式：`v1.x`、`v1.*` 和 `v*`。由于最宽松的选项决定行为，分支 `v1.x`的最终权限为：

- **允许强制推送**：在这三个设置中，`Yes` 最宽松，
  因此决定分支行为。即使该分支还匹配 `v1.x` 和 `v*`
  （它们各自具有更严格的权限），任何可以推送到此分支的用户也可以强制推送。

<a id="code-owner-approval"></a>

## 代码所有者审批

{{< details >}}

- Tier: 专业版，旗舰版
- Offering: JihuLab.com，私有化部署

{{< /details >}}

与推送和合并权限以及强制推送权限不同，代码所有者审批使用最严格的规则。如果某个分支受多条规则保护，只要任一
适用规则启用了 **需要代码所有者审批**，就需要代码所有者审批。更多信息，请参见
[要求代码所有者审批](protected.md#require-code-owner-approval)。

例如，考虑以下规则：

| 分支名称模式 | 需要代码所有者审批 |
|---------------------|------------------------------|
| `v1.x`              | 是                          |
| `v1.*`              | 否                           |
| `v*`                | 否                           |

名为 `v1.x`的分支匹配全部三个分支名称模式：`v1.x`、`v1.*` 和 `v*`。由于至少有一条规则（`v1.x`）需要代码所有者审批，所有发往此分支的合并请求在合并前都需要由代码所有者批准。

<a id="rules-across-groups-and-projects"></a>

## 跨群组和项目的规则

分支保护规则既可以在群组中设置，也可以在项目中设置：

- 群组规则应用于群组中的所有项目，且无法从项目设置中修改。
- 项目规则仅应用于设置它们的项目。

当群组规则和项目规则都匹配某个分支时，极狐GitLab 会一起评估所有匹配的规则：

- 对于大多数设置，以最宽松的规则为准。
- 对于[代码所有者审批](#code-owner-approval)，以最严格的规则为准。

您无法从项目设置中编辑或移除群组规则，但可以为同一分支添加项目规则。合并评估可能导致比单独使用群组规则更宽松的行为。

例如：

- 针对 `main`的群组规则不允许强制推送。
- 项目维护者为 `main` 添加了一条允许强制推送的项目规则。
- 两条规则会一起评估。以最宽松的规则为准，
  因此该项目的 `main` 分支允许强制推送。

<a id="multiple-branch-rule-examples"></a>

## 多分支规则示例

以下示例演示不同规则如何影响分支保护。

<a id="allowed-to-merge"></a>

### 允许合并

一个示例，说明精确分支名称不会覆盖更宽松的通配符模式。

| 分支模式 | 允许合并          |
|----------------|---------------------------|
| `release-v1.0` | 任何人都不可以                    |
| `release*`     | 维护者                |
| `*`            | 开发者 + 维护者    |

- 分支 `release-v1.0` 匹配全部三个模式。以最宽松的规则为准：
  - **允许合并**：开发者 + 维护者可以合并（来自 `*` 规则）。

<a id="allowed-to-push-and-merge"></a>

### 允许推送和合并

一个示例，说明多条分支规则如何应用于不同的分支名称。

| 分支模式 | 允许合并       | 允许推送和合并 |
|----------------|------------------------|---------------------------|
| `main`         | 维护者             | 任何人都不可以                    |
| `m*`           | 开发者 + 维护者 | 开发者 + 维护者    |
| `r*`           | 任何人都不可以                 | 任何人都不可以                    |

- 分支 `main` 匹配两个模式（`main` 和 `m*`）。以最宽松的规则为准：
  - **允许合并**：开发者 + 维护者可以合并（来自 `m*` 规则）。
  - **允许推送和合并**：开发者 + 维护者可以推送（来自 `m*` 规则）。
- 分支 `release-v1.0` 匹配一个模式：
  - **允许合并**：任何人都不可以合并（来自 `r*` 规则）。
  - **允许推送和合并**：任何人都不可以推送（来自 `r*` 规则）。

<a id="code-owner-requirements"></a>

### 代码所有者要求

代码所有者审批的工作方式与其他分支保护设置不同。当多条规则匹配时，以最严格的规则为准，而不是最宽松的规则。

| 分支模式 | 需要代码所有者审批 |
|----------------|------------------------------|
| `production`   | 是                          |
| `prod*`        | 否                           |
| `p*`           | 是                          |

- 分支 `production` 匹配全部三个模式。以最严格的规则为准：
  - **代码所有者审批**：需要（来自 `production` 和 `p*` 规则）。
- 分支 `product-v1.0` 匹配两个模式（`prod*` 和 `p*`）。以最严格的规则为准：
  - **代码所有者审批**：需要（来自 `p*` 规则）。

<a id="ensure-strict-protection"></a>

### 确保严格保护

为确保严格保护不会被更宽松的模式覆盖，请为所有匹配模式配置相同的严格设置。

| 分支模式 | 允许合并 | 允许推送和合并 |
|----------------|------------------|---------------------------|
| `production`   | 维护者       | 任何人都不可以                    |
| `prod*`        | 维护者       | 任何人都不可以                    |
| `p*`           | 维护者       | 任何人都不可以                    |
| `*`            | 维护者       | 任何人都不可以                    |

现在分支 `production` 具有严格的推送权限，因为所有匹配规则都指定**任何人都不可以**推送。
