自定义任务流是 AI 驱动的任务流，您可以创建并配置它们，以自动执行极狐GitLab 项目中复杂的多步骤任务。

<a id="prerequisites"></a>

## 先决条件

- 满足[极狐GitLab Duo Agent Platform 的先决条件](../_index.md#prerequisites)。
- 已[开启自定义任务流](#turn-custom-flows-on-or-off)。

<a id="flow-visibility"></a>

## 任务流可见性

创建自定义任务流时，您需要选择一个项目来管理它，并选择该任务流是公开、私有还是受限。

公开任务流：

- 实例上的任何人都可以查看，并且可以在任何满足先决条件的项目中启用。

受限任务流：

- 管理项目所属顶级群组中任何项目的成员都可以查看和使用。
- 可以在同一顶级群组中的其他项目中开启。
- 无法在该顶级群组之外查看或开启。
- 无法在探索页面的 AI 目录中查看。
- 只能从项目中创建，不能从探索页面的 AI 目录中创建。

如果该任务流已被该顶级群组之外的项目开启，则无法将其设为受限。

私有任务流：

- 仅以下人员可以查看：
  - 管理项目中拥有访客、计划者、报告者、开发者、维护者或所有者角色的成员。
  - 拥有顶级群组所有者角色的用户。
- 无法在管理项目以外的项目或顶级群组以外的群组中启用。

如果该任务流已被管理项目以外的项目开启，则无法将公开或受限任务流设为私有。

## 查看项目的任务流

先决条件：

- 您必须拥有该项目的开发者、维护者或所有者角色。

要查看与您的项目关联的任务流列表：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的项目。
1. 在左侧边栏中，选择 **AI** > **任务流**。
   - 要查看项目中已启用的任务流，请选择**已启用**标签页。
   - 要查看由项目管理的任务流，请选择**已管理**标签页。

选择某个任务流以查看其详细信息。

<a id="create-a-flow"></a>

## 创建任务流

VS Code 中的极狐GitLab 任务流构建器由 VS Code 扩展设置 `gitlab.featureFlags.flowBuilder` 控制。

您可以从项目、使用 AI 目录，或使用 VS Code 中的极狐GitLab 任务流构建器创建任务流。

> [!note]
> 您无法定义自定义任务流来从项目或 AI 目录中调用特定的自定义 Agent。自定义任务流会根据其 YAML 配置创建并使用自己的 Agent。

先决条件：

- 您必须拥有该项目的维护者或所有者角色。

{{< tabs >}}

{{< tab title="从项目" >}}

要创建任务流：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的项目。
1. 在左侧边栏中，选择 **AI** > **任务流**。
1. 选择**新建任务流**。
1. 在**基本信息**下：
   1. 在**显示名称**中，输入名称。
   1. 在**描述**中，输入描述。
1. 在**可见性与访问权限**下，为**可见性**选择**私有**、**受限**或**公开**。
1. 在**配置**下：
   1. 选择**任务流**。
   1. 在编辑器中，输入您的任务流配置：

      - 有关 YAML 语法和架构的更多信息，请参阅[自定义任务流 YAML 架构](custom_flows_schema.md)。
1. 选择**创建任务流**。

{{< /tab >}}

{{< tab title="AI Catalog" >}}

1. 在顶部栏中，选择**搜索或跳转到** > **探索**。
1. 选择 **AI 目录**，然后选择**任务流**标签页。
1. 选择**新建任务流**。
1. 在**基本信息**下：
   1. 在**显示名称**中，输入名称。
   1. 在**描述**中，输入描述。
1. 在**可见性与访问权限**下，为**可见性**选择**私有**或**公开**。
1. 在**配置**下：
   1. 选择**任务流**。
   1. 在编辑器中，输入您的任务流配置：

      - 有关 YAML 语法和架构的更多信息，请参阅[自定义任务流 YAML 架构](custom_flows_schema.md)。
1. 选择**创建任务流**。

{{< /tab >}}

{{< tab title="VS Code" >}}

先决条件：

- [安装并配置 GitLab for VS Code 扩展](../../../editor_extensions/visual_studio_code/setup.md)。
- 启用 `gitlab.featureFlags.flowBuilder` VS Code 扩展设置。
- 要运行任务流：必须为项目开启极狐GitLab Duo Agent Platform，并且您必须至少拥有开发者角色。
- 要将任务流发布到 AI 目录：拥有管理项目的维护者或所有者角色。

> [!note]
> 当您从极狐GitLab 任务流构建器发布任务流时，只有**私有**和**公开**可见性选项可用。
> **受限**可见性选项仅在您从极狐GitLab UI 创建任务流时可用。

在 VS Code 中，您可以使用极狐GitLab 任务流构建器创建自定义任务流。

1. 在 VS Code 中，在您的项目里打开一个新的 YAML 文件。
1. 在 YAML 文件中，选择**打开极狐GitLab 任务流构建器**。
1. 选择以下组件来构建任务流。填写字段：
   - **Agent**：使用工具执行多步骤推理，并不断迭代，直到完成其目标。
   - **工具**：使用固定输入运行单个特定工具；具有确定性，不涉及 LLM。
   - **AI 任务**：进行一次 LLM 调用，产生一个结果（例如，总结、分类或起草）。
     当您需要单个模型响应而非多步骤工作时，请使用 **AI 任务**而不是 **Agent**。
     Agent 在循环中运行并可以使用工具；AI 任务进行一次模型调用并返回一个结果。
   - **人工输入**：暂停任务流，等待用户输入或批准后再继续。
1. 可选。编辑 YAML 文件以更新任务流，并在极狐GitLab 任务流构建器中检查该任务流。

   > [!note]
   > 任务流 YAML 必须符合 [flow registry v1 规范](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/blob/main/docs/flow_registry/v1.md)语法。
1. 要测试您的任务流，请选择**运行**。在**执行控制台**中，选择**执行**。
   检查任务流输出，并根据需要更新任务流。
1. 选择**保存**或**另存为**以保存任务流。
1. 要将任务流发布到 AI 目录，请选择**发布**并填写字段。

> [!note]
> 极狐GitLab 任务流构建器可以将任务流发布到 AI 目录，但在项目中启用任务流以及附加触发器只能在极狐GitLab UI 中完成。

<a id="enable-a-flow"></a>

## 启用任务流

启用任务流，以便从议题、合并请求或讨论中触发它。

当您在项目中启用任务流时：

- 该任务流会同时在该项目的顶级群组中启用。
- 您需要添加一个[触发器](../triggers/_index.md)来指定哪些事件触发该任务流。部分触发器事件涉及服务账号用户。有关更多信息，请参阅[复合身份](../composite_identity.md)。

先决条件：

- 您必须拥有该项目的维护者或所有者角色。

{{< tabs >}}

{{< tab title="从管理项目" >}}

要启用任务流：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的项目。
1. 在左侧边栏中，选择 **AI** > **任务流**。
1. 选择**已管理**标签页，然后选择您要启用的任务流。
1. 在右上角，选择**启用**。
1. 在**项目**下，选择您要在其中启用该任务流的项目。
1. 对于**添加触发器**，选择：
   - [触发任务流的事件类型](../triggers/_index.md#trigger-event-types)。
   - 如果触发器事件类型需要，选择触发器事件操作。
1. 选择**启用**。

{{< /tab >}}

{{< tab title="从 AI Catalog" >}}

要启用任务流：

1. 在顶部栏中，选择**搜索或跳转到** > **探索**。
1. 选择 **AI 目录**，然后选择**任务流**标签页。
1. 选择您要启用的任务流。
1. 在右上角，选择**启用**。
1. 在**项目**下，选择您要在其中启用该任务流的项目。

   要为多个项目启用公开或受限任务流，请从**项目**下拉列表中选择相关项目。您最多可以选择 100 个项目。

1. 对于**添加触发器**，选择：
   - [触发任务流的事件类型](../triggers/_index.md#trigger-event-types)。
   - 如果触发器事件类型需要，选择触发器事件操作。
1. 选择**启用**。

{{< /tab >}}

{{< /tabs >}}

该任务流会出现在群组和项目的 **AI** > **任务流**页面中。顶级群组中任何项目的成员现在都可以在其项目中启用该任务流。

群组中会创建一个服务账号。该账号的名称遵循以下命名约定：`ai-<flow>-<group>`。

<a id="enable-in-a-project"></a>

### 在项目中启用

如果任务流已在顶级群组中启用，您可以在该群组的项目中启用它。

先决条件：

- 您必须拥有该项目的维护者或所有者角色。
- 该任务流必须已在项目的顶级群组中启用。

要在项目中启用任务流：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的项目。
1. 在左侧边栏中，选择 **AI** > **任务流**。
1. 在右上角，选择**从群组启用任务流**。
1. 从下拉列表中，选择您要启用的任务流。
1. 对于**添加触发器**，选择：
   - [触发任务流的事件类型](../triggers/_index.md#trigger-event-types)。
   - 如果触发器事件类型需要，选择触发器事件操作。
1. 选择**启用**。

该任务流会出现在项目的 **AI** > **任务流**列表中。

顶级群组的服务账号会添加到该项目中。该账号会被分配开发者角色。

<a id="disable-a-flow"></a>

## 禁用任务流

先决条件：

- 对于群组，您必须拥有维护者或所有者角色。
- 对于项目，您必须拥有维护者或所有者角色。

要禁用任务流：

1. 在顶部栏中，选择**搜索或跳转到**，然后找到您的群组或项目。
1. 选择 **AI** > **任务流**。
1. 找到您要移除的任务流，然后选择**操作** ({{< icon name="ellipsis_v" >}}) > **禁用**。
1. 在确认对话框中，选择**禁用**。

该任务流不再出现在项目或群组中，并且无法运行。与该任务流关联的任何服务账号或触发器也会被移除。

<a id="use-a-flow"></a>

## 使用任务流

先决条件：

- 您必须拥有该项目的开发者、维护者或所有者角色。
- 该任务流必须已在项目中启用。

要使用任务流：

1. 在您的项目中，打开一个议题、合并请求或史诗。
1. 要触发任务流，请提及、指派任务流服务账号用户，或请求其进行评审。默认情况下，该用户的名称为 `ai-<flow>-<group>`。

   例如，如果您在 `GitLab Duo` 群组中启用一个名为 `Security scanner`的任务流，则服务账号用户为 `ai-security-scanner-gitlab-duo`。
1. 任务流完成任务后，您会看到确认信息，以及一个可合并的变更或一条行内评论。

> [!warning]
> 该服务账号可以访问同时满足以下两个条件的所有项目：
>
> - 您有权访问。
> - 该任务流已添加到其中。

<a id="authenticate-to-the-gitlab-api"></a>

## 向极狐GitLab API 进行身份验证

自定义任务流有一个极狐GitLab OAuth 令牌，可通过 `GITLAB_TOKEN` 使用（也以 `GITLAB_OAUTH_TOKEN`的形式提供）。
这些令牌仅限于授予它们的范围。它们只能访问[具有 `ai_workflows` 范围的极狐GitLab API 端点](foundational_flows/software_development.md#apis-that-the-flow-has-access-to)。
即使令牌发送正确，该范围之外的端点也会被拒绝。

如果您编写直接调用极狐GitLab API 的脚本，请将令牌作为 `Authorization: Bearer` 令牌发送。如果您使用 `PRIVATE-TOKEN` 请求头发送令牌，API 会返回 `401 Unauthorized`。

```shell
curl --header "Authorization: Bearer $GITLAB_TOKEN" \
  "$GITLAB_BASE_URL/api/v4/user"
```

任务流的内置工具和 `glab` CLI 会正确调用 API。

<a id="group-sharing-and-flows"></a>

## 群组共享与任务流

当您在群组中启用任务流时，会自动创建一个相关的服务账号。该服务账号：

- 使用[复合身份验证](../composite_identity.md)来确保任务流的访问权限永远不会超过运行该任务流的用户。
- 会作为成员添加到启用该任务流的顶级群组下的任何项目中，因此该任务流无法访问该群组之外的资源。
- 会被授予对与顶级群组共享的任何其他群组的访问权限。在群组共享方面，该服务账号会被视为与其他群组成员相同。

> [!note]
> 在多个顶级群组之间共享任务流服务账号可能会产生意外的访问权限和安全风险。

<a id="turn-custom-flows-on-or-off"></a>

## 开启或关闭自定义任务流

默认情况下，自定义任务流处于开启状态。您可以为顶级群组或实例开启或关闭它们。

当自定义任务流关闭时：

- 用户无法创建、启用、禁用或执行自定义任务流。
- 现有自定义任务流不再显示在项目的 **AI** > **任务流** > **已启用**下。
- 在项目中创建的自定义任务流会显示在 **AI** > **任务流** > **已管理**下，但无法执行。
- [内置任务流](foundational_flows/_index.md)仍然可用。

1. 在左侧边栏中，选择**设置** > **极狐GitLab Duo**。
