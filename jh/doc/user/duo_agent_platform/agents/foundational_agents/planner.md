计划者 Agent 是一个专门的 AI Agent，可协助进行极狐GitLab 中的产品管理和规划工作流程。它帮助你更高效地创建、排定优先级和跟踪工作。

计划者 Agent 理解极狐GitLab 的规划概念，包括工作项层级（史诗、议题和任务）、里程碑、标签和权重。它可以分析工作项，建议优先级排序策略，并帮助你构建和传达计划。

在以下情况下使用计划者 Agent：

- 优先级排序：应用 RICE、MoSCoW 或 WSJF 等框架对工作项进行排序。
- 工作分解：将计划分解成史诗、特性和用户故事。
- 创建内容：起草备忘录、需求和其他规划产物，或直接在被要求时创建史诗、议题和任务。
- 依赖关系分析：识别被阻塞的工作并理解项目间的关系。
- 编辑内容：更新工作项、标签、里程碑和其他属性，可以在被请求时或在它请求确认后执行操作。
- 待办管理：为工作项添加待办事项并将其标记为完成。
- 计划会议：组织冲刺、里程碑或季度规划。
- 状态报告：生成进度、风险和阻碍的总结。
- 待办积压管理：识别过时的议题、重复项或需要细化的项目。
- 估算：提供工作项的相对规模或工作量估计。

<a id="use-the-planner-agent"></a>

## 使用计划者 Agent

你可以在极狐GitLab UI 中使用计划者 Agent。

<a id="tips-for-best-results"></a>

### 最佳结果提示

为获得最佳结果，请遵循以下建议：

- 提供有关请求的上下文，例如 URL、筛选条件或范围。
- 在相关时指定工作项类型（史诗、议题或任务）。
- 如果你有偏好的优先级框架，请指定。
- 在要求总结或更新时，请指定目标受众，例如工程团队、领导层或利益相关者。
- 当你希望 Agent 执行操作而非提供建议时，请使用明确的动作动词，如“创建”、“更新”或“关闭”。
- 如果 Agent 的假设不符合你的工作流程，请要求澄清。

<a id="in-the-gitlab-ui"></a>

### 在极狐GitLab UI 中

先决条件：

- [开启](_index.md#turn-foundational-agents-on-or-off)内置 Agent。

要在极狐GitLab UI 中使用计划者 Agent：

1. 在顶部栏中，选择 **搜索或跳转到** 并查找你的项目或群组。
1. 在极狐GitLab Duo 侧边栏中，选择 **新会话** ({{< icon name="pencil-square" >}})。
1. 从下拉列表中选择 **计划者**。

   聊天对话打开在屏幕右侧的极狐GitLab Duo 侧边栏中。
1. 输入你的规划相关问题或请求。

<a id="example-prompts"></a>

## 示例提示

- 优先级排序：
  - "帮助我使用 RICE 框架对带有标签 `<标签名>` 的积压工作项进行优先级排序。"
  - "使用 MoSCoW 根据以下条件对此工作项中的特性进行分类：`<条件>`，基于客户影响：`<URL>`"
  - "按第一季度的战略价值对这些工作项进行排序：`<URLs>`"
  - "使用努力与影响矩阵比较这些特性：`<URLs>`"
  - "为了按时完成，我应该从当前范围中移除此工作项下的哪些子项？`<URL>`"
- 工作分解：
  - "将此计划分解为我们需要交付的关键特性：`<URL>`"
  - "实现此工作项需要哪些任务？`<URL>`"
  - "此特性的 MVP 版本是什么？`<URL>`"
  - "我们应该如何对此工作项中的特性进行排序？`<URL>`"
  - "为此项目建议分阶段的方法：`<URL>`"
- 状态报告：
  - "提供此工作项的状态更新和进度报告，包括所有子项：`<URL>`"
  - "生成此工作项进度的执行摘要：`<URL>`"
  - "为领导层总结阻碍和缓解计划：`<URL>`"
  - "撰写有关此计划的状况的利益相关者更新：`<URL>`"
- 内容创建：
  - "为此计划起草一份备忘录，包括目标、成功标准和关键利益相关者：`<URL>`"
  - "为此起草一份技术需求工作项，包括 API 需求、数据模型和集成点：`<URL>`"
  - "撰写一份依赖关系图叙述，解释这些工作项之间的关系和排序：`<URLs>`"
  - "为此史诗生成风险评估，识别潜在阻碍和缓解策略：`<URL>`"
  - "估计此工作项的实施工作量，包括开发时间、测试和潜在阻碍：`<URL>`"
- 依赖关系分析：
  - "我们应该推迟此工作项中的哪些工作以减少范围？`<URL>`"
  - "帮助我在技术债务和新特性之间进行优先级排序。"
- 计划会议：
  - "将这些工作项分组到逻辑发布主题中：`<URLs>`"
  - "哪些工作项已经错过了截止日期？"
- 待办积压管理：
  - "查找 6 个月内未更新的过时工作项。"
  - "识别此项目中的重复或类似工作项。"
  - "显示指派给我的工作项。"
- 内容编辑：
  - "将此工作项关闭为已完成，并创建一个新的回顾工作项，记录做得好的地方和需要改进的地方：`<URL>`"
- 待办管理：
  - "为此工作项添加一个待办事项：`<URL>`"
  - "将此工作项的所有待办事项标记为完成：`<URL>`"

<a id="known-issues"></a>

## 已知问题

- Agent 可以批量分析工作项，但对于涉及大量项目的请求，响应质量可能会下降。
- Agent 无法可靠地访问讨论历史很长的工作项上的评论。超过约 100 条的评论历史可能不完整。
- 当你要求 Agent 将工作项的状态更新为一个不存在的值时，Agent 可能会错误地报告更新成功，而实际上没有应用任何更改。
- Agent 无法在工作项之间创建关联项关系。但是，你可以要求 Agent 使用 `/relate`、`/blocks` 或 `/blocked_by` 快速操作添加评论作为变通方法。
