面向管理员的极狐GitLab 合规功能可确保您的极狐GitLab 实例符合常见的合规标准。其中许多功能也适用于群组和项目。

<a id="compliant-workflow-automation"></a>

## 合规工作流自动化

对于合规团队而言，不仅要确保其控制措施和要求已正确设置，还要确保它们始终保持正确设置，这一点非常重要。一种做法是定期手动检查设置，但这种方式容易出错且耗时。更好的方法是使用单一可信来源的设置和自动化，确保合规团队配置的内容始终保持配置状态并正常运行。以下功能可帮助您实现合规自动化：

| 功能                                                                                                                                       | 实例                             | 群组                               | 项目                              | 描述 |
|:----------------------------------------------------------------------------------------------------------------------------------------------|:--------------------------------------|:-------------------------------------|:--------------------------------------|:------------|
| [合并请求审批策略审批设置](../../user/application_security/policies/merge_request_approval_policies.md#approval_settings) | {{< yes >}} | {{< yes >}} | {{< yes >}} | 强制执行一项合并请求审批策略，要求多个审批人，并在极狐GitLab 实例或群组中所有已强制执行的群组或项目内覆盖各种项目设置。 |

<a id="audit-management"></a>

## 审计管理

任何合规计划的一个重要组成部分，就是能够回溯并了解发生了什么、何时发生以及由谁负责。您可以在审计场景中使用这一点，也可以在问题发生时用于了解其根本原因。

同时拥有底层原始审计数据列表和高层汇总审计数据列表会很有帮助。借助这两者，合规团队可以快速判断是否存在问题，然后深入查看这些问题的具体细节。以下功能可帮助您了解极狐GitLab 中的情况并审计正在发生的事情：

| 功能                                           | 实例   | 群组      | 项目    | 描述 |
|:--------------------------------------------------|:------------|:------------|:------------|:------------|
| [审计事件](audit_event_reports.md)            | {{< yes >}} | {{< yes >}} | {{< yes >}} | 为维护代码的完整性，审计事件让管理员能够在高级审计事件系统中查看极狐GitLab 服务器中所做的任何修改，以便您控制、分析和跟踪每一项变更。 |
| [审计报告](audit_event_reports.md)           | {{< yes >}} | {{< yes >}} | {{< yes >}} | 基于已发生的审计事件创建并访问报告。使用极狐GitLab 预置报告，或通过 API 构建您自己的报告。 |
| [审计事件流](audit_event_streaming.md) | {{< yes >}} | {{< yes >}} | {{< yes >}} | 将极狐GitLab 审计事件流式传输到 HTTP 端点或第三方服务，例如 AWS S3 或 GCP Logging。 |
| [审计员用户](../auditor_users.md)              | {{< yes >}} | {{< no >}}  | {{< no >}}  | 审计员用户是指被授予对极狐GitLab 实例上所有项目、群组和其他资源的只读访问权限的用户。 |

<a id="policy-management"></a>

## 策略管理

组织有独特的策略要求，这些要求可能来自组织标准，也可能来自监管机构的强制规定。以下功能可帮助您定义规则和策略，以遵循工作流要求、职责分离和安全供应链最佳实践：

| 功能                                                                          | 实例   | 群组      | 项目    | 描述 |
|:---------------------------------------------------------------------------------|:------------|:------------|:------------|:------------|
| [凭据清单](../credentials_inventory.md)                             | {{< yes >}} | {{< no >}}  | {{< no >}}  | 跟踪极狐GitLab 实例中所有用户使用的凭据。 |
| [精细用户角色<br/>和灵活权限](../../user/permissions.md)    | {{< yes >}} | {{< yes >}} | {{< yes >}} | 通过五种不同的用户角色和外部用户设置来管理访问和权限。根据人员的角色设置权限，而不是仅授予对代码仓库的读取或写入访问权限。不要将源代码分享给只需要访问议题跟踪器的人员。 |
| [合并请求审批](../../user/project/merge_requests/approvals/_index.md) | {{< yes >}} | {{< yes >}} | {{< yes >}} | 配置合并请求所需的审批。 |
| [推送规则](../../user/project/repository/push_rules.md)                        | {{< yes >}} | {{< yes >}} | {{< yes >}} | 控制对代码仓库的推送。 |
| [安全策略](../../user/application_security/policies/_index.md)          | {{< yes >}} | {{< yes >}} | {{< yes >}} | 配置可自定义的策略，这些策略根据策略规则要求合并请求审批，或为满足合规要求强制安全扫描器在项目流水线中执行。策略可以针对特定项目精细强制执行，也可以针对群组或子群组中的所有项目强制执行。 |
